# 주요 용어

책에서 쓰는 의미를 짧게 재구성했다. 한글 용어는 가나다순, 영문 표기는 끝에 둔다. 자세한 설명은 장 파일에서 확인한다.

- **가데이터** — 테이블 구조·참조·작동 규칙을 검증하는 시험 입력값. (ch11)
- **객체** — 고유 정보와 특성을 가진 게임의 대상. (ch05)
- **고정 기획 데이터** — 설계 규칙·기준값을 관리하는 데이터로 개인 플레이 상태와 구별한다. (ch05, ch10)
- **기능 단위 분해** — 시스템의 행위·동작을 나누고 조건과 관계를 정리하는 작업. (ch05)
- **기본 키** — 테이블의 각 행을 구별하는 기준 식별자. (ch10–11)
- **기본값** — UI나 데이터가 처음 적용될 때 사용하는 값·상태. (ch10, ch15)
- **기획 의도** — 시스템의 존재 이유와 구체적 설계 선택을 이끄는 기준. (ch03–04)
- **데이터 테이블** — 기획자가 관리할 수치·정보를 구조화한 표. (ch10–12)
- **라이브 서비스** — 출시 이후 운영·개선·이슈 대응 단계. (ch20)
- **랜덤 풀** — 무작위 선택의 후보 집합. 비중은 집합 안의 상대 비율이다. (ch12)
- **레퍼런스** — 목적과 맥락을 분석해 설계에 활용하는 참고 사례. (ch04, ch21)
- **메타포** — 익숙한 대상에 빗대어 인터페이스 의미를 전달하는 표현. (ch14)
- **모달** — 배경 조작을 막고 특정 행동·결정을 요구하는 팝업. (ch16)
- **모듈화** — 재사용·연결이 가능한 단위로 시스템을 구성하는 방식. (ch06)
- **배지** — 미확인 신규 항목을 점·숫자 등으로 표시하는 알림. (ch16)
- **속성** — 객체의 정보나 특징을 나타내는 값. (ch05)
- **속성 단위 분해** — 객체들의 공통 정보와 서로 다른 값을 구조화하는 작업. (ch05)
- **스트링 키** — 언어별 문자열을 직접 복사하지 않고 참조하는 식별자. (ch12)
- **시스템 기획** — 게임의 규칙·구조·흐름과 상호 작용을 설계하는 일. (ch01)
- **시스템 기획서** — 도입 판단과 협업·구현에 필요한 설계를 전달하는 문서. (ch17–19)
- **역방향 점검** — 복잡한 UI에서 시스템 규칙·구조의 문제를 되짚는 방법. (ch16)
- **예외 처리** — 정상 흐름 밖 조건의 판단·처리·안내를 정하는 설계. (ch07–09)
- **와이어프레임** — 화면 구성과 요소 배치를 구조 중심으로 나타내는 설계도. (ch15)
- **외래 키** — 다른 테이블의 정의를 참조해 데이터를 연결하는 키. (ch10–11)
- **자료형** — 값의 종류와 허용 형식을 구별하는 데이터 규격. (ch10–12)
- **정보 구조도** — 정보·기능의 계층 관계를 정리한 도구. (ch15)
- **참조** — 정보를 중복 작성하는 대신 식별자로 기존 정의를 연결하는 방식. (ch11–12)
- **콘텐츠 기획** — 시스템 구조 안에 들어가는 구체적 플레이 내용을 설계하는 일. (ch01)
- **키** — 행이나 데이터를 구별하거나 연결하기 위한 식별자. (ch10–12)
- **트리거** — 규칙이나 처리를 시작시키는 행위·조건. (ch05–07)
- **플레이어 데이터** — 개별 플레이 중 생성·변경·저장되는 상태 정보. (ch05, ch10)
- **플로 차트** — 처리 순서·판정·분기를 기호와 연결선으로 표현한 도식. (ch09)
- **하드코딩** — 조정할 값을 코드 안에 직접 넣는 방식. (ch10)
- **ENUM** — 허용 항목 목록으로 분류 값을 제한하는 자료형. (ch10)
- **ERD** — 테이블과 키의 관계를 시각화한 엔티티 관계도. (ch11)
- **IA** — 정보 구조도. 정보·기능의 계층과 탐색 관계를 나타낸다. (ch15)
- **UI** — 플레이어가 정보를 보고 기능을 조작하는 인터페이스. (ch13–16)
- **UI 플로 차트** — 화면 전환과 인터랙션 흐름을 표현한 도식. (ch15)
- **UX** — 기능 이용 과정에서 플레이어가 겪는 경험. (ch13–16)
