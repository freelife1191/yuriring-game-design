# 04. 기획 의도 설계: 문제·역할·감정·흐름을 근거로 묶는다

**참고 범위:** 책 56–77쪽 / PDF 58–79쪽. 마지막 PART 03 안내(PDF 79쪽)는 제외했다.

## 핵심 관점

의도는 사유서 한 줄이 아니라, 규칙·예외·데이터·UI의 선택을 묶는 설계 구조다. 저자는 **문제 정의 → 역할 정의 → 감정 설계 → 플레이 흐름 설계** 순서로 의도를 구체화하고, 이후 여섯 질문으로 타당성을 검토하라고 제안한다(책 58–61, 69–73쪽 / PDF 60–63, 71–75쪽).

## 의도를 설계하는 네 단계

1. **문제 정의:** 어느 행동/콘텐츠가 왜 필요한지 적는다. 일일 퀘스트라면 접속 유도, 반복의 지루함 완화, 메인 퀘스트 밖 성장 기회의 문제가 출발점이다(책 58쪽 / PDF 60쪽).
2. **역할 정의:** 전체 루프에서 차지할 비중과 연결 대상을 정한다. 일일 퀘스트는 접속 유도뿐 아니라 성장 보조, 초보자 학습, 사용률 낮은 콘텐츠의 트리거가 될 수 있다(책 59쪽 / PDF 61쪽). 따라서 목표·보상·해금 조건은 핵심 콘텐츠를 대체하지 않도록 정한다.
3. **감정 설계:** 반복이 숙제가 되지 않게, 완료 시 효과·낮은 수령 마찰·누적 성취 피드백을 정한다. 감정은 ‘좋아 보임’이 아니라 완료 판정 후의 연출, 자동/클릭 수령, 보상 위치 같은 결정으로 구현된다(책 60쪽 / PDF 62쪽).
4. **플레이 흐름 설계:** UI 진입 → 오늘의 목표 인지 → 여러 퀘스트 병행 → 완료·보상 → 다음 행동의 순서를 설계한다. 목표 인지와 보상 방식은 각각 집중과 성취감에 영향을 준다(책 61쪽 / PDF 63쪽).

## 의도 깊이와 설득 규칙

‘리텐션을 높인다’나 ‘매출을 올린다’는 판단 기준이 될 수 없다. 대상 플레이어, 원하는 체험, 설계 방향, 기대 효과를 적어야 수치·파괴 위험·보호 장치·성공 연출의 선택이 연결된다(책 62–66쪽 / PDF 64–68쪽).

중요한 도입 제안은 아래 여섯 질문을 기준으로 검토한다. 제안의 규모와 미결정 사항에 맞춰 설명 깊이를 조정한다.

1. 왜 이 기능이 필요하며 왜 지금인가?
2. 없으면 어떤 문제가 생기며 왜 지금 해결해야 하는가?
3. 도입 뒤 어떤 행동·감정·흐름 변화가 나고, 왜 긍정적인가?
4. 기존 시스템과 무엇이 다르고 어디와 충돌할 수 있는가?
5. 악용·피로·균형 붕괴 같은 리스크와 대응은 무엇인가?
6. 위 주장을 뒷받침할 플레이 관찰, 데이터, 피드백, 유사 구조의 근거는 무엇인가?

플레이어 의견, 이론, 타 게임 사례, 지표 한 줄은 답 그 자체가 아니라 해석할 재료다. 발생 맥락과 우리 게임의 구조적 유사성까지 연결해야 한다(책 67–72쪽 / PDF 69–74쪽).

## 원문 사례를 실무 형식으로 재구성: 장비 프리셋

**원문 사례 재구성** — 다양한 콘텐츠에 장비 세팅을 반복 교체하는 상황의 프리셋 제안이다(책 70–72쪽 / PDF 72–74쪽).

| 층위 | 적용 |
| --- | --- |
| 문제/역할 | 전환 때의 수동 교체·실수 때문에 콘텐츠 진입을 포기하는 문제를 줄여, 여러 콘텐츠를 연결한다. |
| 규칙 | 허용된 장비 세트를 저장·불러오며, 사용 가능 시점·슬롯 수·교체 조건을 정의한다. |
| 데이터 | 프리셋 슬롯, 슬롯별 장비 참조, 해금 조건, 콘텐츠별 제약 여부를 관리한다. |
| UI | 초반에는 부담을 줄이도록 해금 뒤 노출하고, 직관적 이름과 저장/불러오기 결과를 분명히 보여 준다. |
| 리스크 | 최적 세팅 압박 및 초보자 복잡도는 슬롯 제한, 성장 단계 해금, 안내 방식으로 완화한다. |

## 레퍼런스 활용과 안티패턴

- **안티패턴: 성공작의 표면을 복사한다.** 장르·대상층·템포·과금·UX 맥락이 다른데 구조만 옮기면 기존 루프와 충돌하거나 피로를 늘린다(책 74–75쪽 / PDF 76–77쪽).
- **활용 순서:** 그 게임에서 왜 작동했는지 → 우리 게임에서는 어떤 문제가 생길지 → 핵심 원리·감정·리듬을 무엇으로 변형할지 분석한다. 레퍼런스는 소통 단축과 검증된 흐름의 출발점이지, 결론이 아니다.
- **안티패턴: UI와 보상을 이유 없이 정한다.** 자동/클릭 수령, 보상 아이콘 위치, 7일/28일 기간, 재료 선택 모두 의도에 대한 답을 가져야 한다(책 65–66쪽 / PDF 67–68쪽).

## 실무 점검

- 문제, 시스템 역할, 목표 감정, 플레이 흐름을 서로 다른 문장으로 적었는가?
- 각 규칙·예외·테이블 필드·UI 요소가 네 단계 중 무엇을 지지하는지 설명되는가?
- 여섯 질문에 ‘편해진다’ 같은 추상 표현 없이 관찰 가능한 행동 변화로 답했는가?
- 리스크 대응이 기능 도입 목표를 무너뜨리지 않는가?
- 레퍼런스의 성공 맥락과 우리 게임의 차이를 함께 기록했는가?
