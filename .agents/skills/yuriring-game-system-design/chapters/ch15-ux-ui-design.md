# 15장 — UX/UI 설계

> 출처: 정윤지(유리링), 『유리링의 실전 게임 시스템 기획』. 위치는 `책 인쇄 쪽 / PDF 쪽`으로 함께 적는다(이 책은 PDF 쪽 = 인쇄 쪽 + 2). 핵심 근거: 책 248–263쪽 / PDF 250–265쪽.

## 핵심 관점

기능이 작동해도 플레이어가 찾고 조작할 수 없으면 사용되지 않는 기능이다(책 250쪽 / PDF 252쪽). 15장은 이를 문서화하는 세 도구(IA, UI 플로 차트, 와이어프레임)와 화면 영역·구성요소 명세로 연결한다. 좋은 UI 문서는 ‘버튼이 있다’가 아니라 **역할, 입력, 결과, 기본값, 예외, 저장, 갱신, 표기 방식**을 팀이 동일하게 구현할 수 있게 만든다는 것은 구성 요소 설계 절(15.3, 책 258–263쪽 / PDF 260–265쪽)의 항목을 묶은 스킬 정리다.

## 적용 절차 — 스킬의 재구성

아래 다섯 단계는 15장의 도구(IA·플로 차트·와이어프레임)와 영역·구성 요소 설계 절을 작업 순서로 정리한 것이다. 단계 문장은 스킬 정리이고, 각 단계 끝의 '참고 원문 절'은 그 단계가 참고한 원문 범위다. 책의 말로 인용할 때는 아래 '핵심 판단 규칙'이나 원문 사례 문장의 쪽을 쓴다.

1. **IA를 그린다.** 화면/정보를 깊이와 그룹으로 배치하고 화살표로 실제 탐색 연결을 표시한다. 누락·중복·불필요한 중첩과 확장성을 먼저 점검한다(참고 원문 절: 책 250–251쪽 / PDF 252–253쪽).
2. **플로 차트로 시간과 분기를 정한다.** 어떤 행동 뒤 어떤 화면·조건·연출·버튼이 어떤 순서로 나오는지 적어 UX 오류와 구현 분기를 드러낸다(참고 원문 절: 책 251–252쪽 / PDF 253–254쪽).
3. **와이어프레임으로 역할과 위치를 검증한다.** 색·이미지보다 기능·영역·반복성·라벨에 집중하고, 흐름과 계층이 드러나도록 흑백·회색 기반 스케치를 권장한다(참고 원문 절: 책 252–253쪽 / PDF 254–255쪽). 원문은 피그마·어도비 XD로 만들면 프로토타입으로 사용 흐름을 시뮬레이션해 사용성 테스트에도 유리하다고 한다(책 253쪽 / PDF 255쪽).
4. **영역 명세를 작성한다.** 화면명, 역할, 구성요소, 배치 이유를 설명해 아티스트와 프로그래머의 구현 기준을 맞춘다(참고 원문 절: 책 254–257쪽 / PDF 256–259쪽). 원문 캐릭터 인벤토리 사례는 상단 공통 영역, 왼쪽 상세 정보, 오른쪽 목록·필터, 중앙 일러스트·주요 버튼, 하단 컨텍스트 버튼(진화·초월·각성)으로 나누고, 왼손은 정보 확인·오른손은 조작 실행이라는 엄지 조작을 배치 의도로 든다. 왼쪽 정보 영역은 계속 바뀌므로 넓게, 오른쪽 목록은 터치 조작 특성상 오른쪽에, 필터·정렬은 공통 메뉴와 겹치지 않게 오른쪽 상단에 둔다(책 255–256쪽 / PDF 257–258쪽). 저자는 각 영역의 내용만으로는 부족하며 '왜 이 위치인가', '왜 이 요소가 이 비중인가'를 설명하고, 첫 진입 화면인지 선택 직후 화면인지 같은 전후 맥락도 고려하라고 한다(책 257쪽 / PDF 259쪽).
5. **컴포넌트 행동을 끝까지 명세한다.** 상호작용, 결과, 닫기 조건, 정렬, 기본값, 저장 위치, 디자인 상태를 정의하고 검색·빈 상태·문자열·시간까지 예외를 점검한다(참고 원문 절: 책 258–263쪽 / PDF 260–265쪽).

## 핵심 판단 규칙

|판단 규칙|조건·방법·이유|
|---|---|
|IA는 메뉴 나열이 아니라 탐색 지도다.|동일 깊이는 같은 줄, 세부 정보는 아래 줄, 화살표로 이동/탐색을 보인다(책 250–251쪽 / PDF 252–253쪽).|
|플로 차트에는 조건 분기를 포함한다.|결과 화면은 경험치·보상·다음 스테이지 유무에 따라 출력 시점이 달라진다(책 252쪽 / PDF 254쪽).|
|와이어프레임은 기능 중심·흑백으로 만든다.|색/이미지보다 역할·위치·계층을 먼저 확인하고 반복 요소를 통일한다(책 252–253쪽 / PDF 254–255쪽).|
|화면마다 이름·역할·요소·배치 이유를 문서화한다.|제작자와 구현자가 목적을 공유할 기준이 된다(책 254쪽 / PDF 256쪽).|
|구성요소에는 닫기 조건과 현재 상태를 적는다.|정렬 드롭다운은 바깥 클릭·재선택 시 닫고 현재 기준은 강조한다(책 258–259쪽 / PDF 260–261쪽).|
|정렬은 기획 의도가 있는 순서로 정의한다.|원문 캐릭터 정렬은 희귀도 > 등급 > 레벨 > 초당 공격력 > 강인함 > 회복력 순이다. 등급·레벨·스테이터스는 진화·레벨 업·장비로 변하므로 플레이어가 기억하는 희귀도를 최상위에 둔다. 기본값은 희귀도·내림차순, 옆의 토글로 오름차순/내림차순을 바꾸며, 선택한 옵션은 클라이언트에 저장해 다시 들어와도 유지한다(책 259쪽 / PDF 261쪽). 검색은 완전 일치·부분 일치 등 우선순위를 명시하지 않으면 기대를 어긴다. 원문은 일반적으로 완전 일치 > 일부 일치 > 최근 접속 순 > 계정 레벨순으로 두는 경우가 많다고 한다(책 259–260쪽 / PDF 261–262쪽).|
|빈 결과는 오류처럼 보이지 않게 설명한다.|‘결과 없음’ 문구와 필요 시 보조 콘텐츠를 제공한다(책 260쪽 / PDF 262쪽).|
|기본값은 반복 행동의 계산 부담을 줄이는 방향으로 정한다.|원문 '라이즈 오브 킹덤즈' 훈련 화면은 두 조건으로 기본값을 정한다. 자원이 충분하고 시스템에 '한 번에 훈련 가능한 최대치'가 따로 설정되어 있으면 그 값(예: 700)을, 자원이 부족하면 보유 자원으로 가능한 실질 최대 수량을 기본값으로 둔다. 실질 최대는 가장 부족한 자원을 기준으로 계산한다. 예: 700명 훈련에 식량·나무가 각각 7.0만 필요하고 식량 6.3만·나무 10만을 보유하면 식량 기준 630명(책 261–262쪽 / PDF 263–264쪽). 값은 사례이며 다른 게임의 기본값이 아니다.|
|저장 범위는 기기 단위/계정 단위의 경험과 비용을 비교해 정한다.|클라이언트 저장은 간단하지만 기기 변경 시 유지되지 않고, 서버 저장은 계정 유지 대신 비용이 늘어난다(책 262쪽 / PDF 264쪽).|
|정보 갱신 주기는 비용과 중요도로 정한다.|자동 갱신이든 수동 새로고침이든 일관되게 처리하고, 서버 비용과 직결되면 "일일 1회 자동 갱신, 그 외는 새로고침 버튼"처럼 조율한다. 기준 질문은 "항상 최신 정보를 유지해야 할 만큼 중요도가 높은가?"다(책 262쪽 / PDF 264쪽).|
|숫자·시간·문자열 표기는 일관된 정책을 둔다.|숫자 약어·한글 표기 기준을 통일하고, 랭킹·경매 종료는 정확한 시각, 친구 접속은 상대 시간이 적합하며 기준 시간대도 명시한다. 다국어 문자열은 말줄임(잘림 위치 주의), 폰트 자동 축소(최소 글자 크기 제한), 흐름 애니메이션(시선 분산 주의) 중 방식을 정하고, UI 시안 단계부터 다국어 샘플로 점검한다(책 262–263쪽 / PDF 264–265쪽).|

## 안티패턴

> 이 절은 원문의 기준을 실패 사례로 정리한 스킬 정리다. `책 X쪽 / PDF Y쪽`이 붙은 항목만 그 쪽에 원문 근거가 있고, 나머지는 저자의 말로 인용하지 않는다.

- IA 없이 화면만 그려 기능 연결·누락·반복 정보를 발견하지 못한다.
- 플로 차트에서 보상 없음, 레벨업 없음, 다음 단계 없음 같은 분기를 빼고 정상 사례만 작성한다.
- 와이어프레임을 완성 디자인처럼 만들며 기능 라벨과 반복 컴포넌트 규칙을 놓친다.
- ‘정렬한다’, ‘저장한다’라고만 쓰고 기본 기준·오름/내림·닫기·저장 위치를 비워 둔다.
- 결과 없음, 긴 문자열, 타임존, 정보 갱신 시점을 후반 구현 이슈로 넘긴다.

## 사례 재구성

**원문 사례 — 게임 클리어 결과 화면(책 251–253쪽 / PDF 253–255쪽).** IA는 클리어 정보·레벨/경험치·보상·재시도/목록/다음 단계의 계층과 연결을 보인다. 플로 차트는 승리→경험치/레벨업 조건→보상 조건→다음 스테이지 조건의 표시 순서를 정한다. 와이어프레임은 그 결과를 모듈과 버튼 영역으로 배치한다. 세 문서가 같은 화면을 정보 구조, 시간 분기, 공간 구조로 각각 검증한다는 대비는 스킬 정리다.

**새 적용 예시 — 우편함 수령 화면.** IA에 우편 목록, 상세, 첨부 보상, 일괄 수령, 빈 상태를 둔다. 플로 차트는 `수령 가능 여부 → 보상 지급 성공/실패 → 배지 갱신 → 상세 닫기`를 분기한다. 와이어프레임은 목록·상세·수령 행동의 영역만 잡는다. 컴포넌트 표에는 기본 정렬, 수령 뒤 목록 갱신, 배지의 저장/갱신 기준, 결과 없음 문구를 적는다.

## 점검 항목

> 스킬이 만든 점검 목록이다. 근거는 위 절들의 쪽 표기를 따른다.

- [ ] IA에 상하위 계층, 그룹, 실제 이동 화살표, 확장 여지가 모두 있는가?
- [ ] 플로 차트가 사용자 행동뿐 아니라 모든 조건 분기와 출력 순서를 담는가?
- [ ] 와이어프레임이 이미지보다 역할·위치·반복성·라벨을 분명히 하는가?
- [ ] 모든 화면에 이름·역할·구성요소·배치 의도가 있는가?
- [ ] 드롭다운/정렬/필터에 기본값, 상태 표시, 닫기, 예외, 저장 위치가 있는가?
- [ ] 검색 결과 없음과 실패·빈 상태가 시스템 오류처럼 보이지 않는가?
- [ ] 갱신 주기·숫자/시간 형식·타임존·다국어 긴 문자열 정책을 정했는가?

## 용어 및 관련 장

- **IA(정보 구조도)**: 정보·콘텐츠의 배치와 탐색 구조를 시각화한 지도(책 250쪽 / PDF 252쪽).
- **UI 플로 차트**: 행동 뒤 화면 이동·선택·조건 분기를 정리한 흐름도(책 251쪽 / PDF 253쪽).
- **와이어프레임**: 디자인 전 기능 요소의 역할·위치·구조를 보는 기초 설계도(책 252쪽 / PDF 254쪽).

정보의 우선순위·깊이·표현은 [14장](ch14-visual-interaction.md), 입력·알림·탐색 컴포넌트의 상세 규칙은 [16장](ch16-ui-components.md), UX/UI의 역할 관계는 [13장](ch13-ux-ui-foundations.md)을 참조한다.

## 원문/OCR 한계

도표의 구조와 본문 설명을 바탕으로 문서화 절차를 정리했다. OCR상 일부 항목명이 흐린 곳은 문맥으로 보완하지 않고, 명확히 확인되는 IA·플로 차트·와이어프레임과 행동 명세만 사용했다.
