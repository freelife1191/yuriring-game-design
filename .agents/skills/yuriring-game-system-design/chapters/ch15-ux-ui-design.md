# 15장 — UX/UI 설계

> 출처: 정윤지(유리링), 『유리링의 실전 게임 시스템 기획』. 이 문서는 **PDF 쪽수**를 쓴다(책 인쇄 쪽수는 PDF보다 2쪽 작음). 핵심 근거: PDF 250~265쪽.

## 핵심 관점

기능이 작동해도 플레이어가 찾고 조작할 수 없으면 사용되지 않는 기능이다(PDF 252쪽). 15장은 이를 문서화하는 세 도구(IA, UI 플로 차트, 와이어프레임)와 화면 영역·구성요소 명세로 연결한다. 좋은 UI 문서는 ‘버튼이 있다’가 아니라 **역할, 입력, 결과, 기본값, 예외, 저장, 갱신, 표기 방식**을 팀이 동일하게 구현할 수 있게 만든다(PDF 260~265쪽).

## 저자 프레임워크/절차

1. **IA를 그린다.** 화면/정보를 깊이와 그룹으로 배치하고 화살표로 실제 탐색 연결을 표시한다. 누락·중복·불필요한 중첩과 확장성을 먼저 점검한다(PDF 252~253쪽).
2. **플로 차트로 시간과 분기를 정한다.** 어떤 행동 뒤 어떤 화면·조건·연출·버튼이 어떤 순서로 나오는지 적어 UX 오류와 구현 분기를 드러낸다(PDF 253~254쪽).
3. **와이어프레임으로 역할과 위치를 검증한다.** 색·이미지보다 기능·영역·반복성·라벨에 집중한 흑백 스케치로 화면 구조를 합의한다(PDF 254~255쪽).
4. **영역 명세를 작성한다.** 화면명, 역할, 구성요소, 배치 이유를 설명해 아티스트와 프로그래머의 구현 기준을 맞춘다(PDF 256~259쪽).
5. **컴포넌트 행동을 끝까지 명세한다.** 상호작용, 결과, 닫기 조건, 정렬, 기본값, 저장 위치, 디자인 상태를 정의하고 검색·빈 상태·문자열·시간까지 예외를 점검한다(PDF 260~265쪽).

## 핵심 판단 규칙

|판단 규칙|조건·방법·이유|
|---|---|
|IA는 메뉴 나열이 아니라 탐색 지도다.|동일 깊이는 같은 줄, 세부 정보는 아래 줄, 화살표로 이동/탐색을 보인다(PDF 253쪽).|
|플로 차트에는 조건 분기를 포함한다.|결과 화면은 경험치·보상·다음 스테이지 유무에 따라 출력 시점이 달라진다(PDF 254쪽).|
|와이어프레임은 기능 중심·흑백으로 만든다.|색/이미지보다 역할·위치·계층을 먼저 확인하고 반복 요소를 통일한다(PDF 254~255쪽).|
|화면마다 이름·역할·요소·배치 이유를 문서화한다.|제작자와 구현자가 목적을 공유할 기준이 된다(PDF 256쪽).|
|구성요소에는 닫기 조건과 현재 상태를 적는다.|정렬 드롭다운은 바깥 클릭·재선택 시 닫고 현재 기준은 강조한다(PDF 260~261쪽).|
|정렬은 기획 의도가 있는 순서로 정의한다.|검색은 완전 일치·부분 일치 등 우선순위를 명시하지 않으면 기대를 어긴다(PDF 261~262쪽).|
|빈 결과는 오류처럼 보이지 않게 설명한다.|‘결과 없음’ 문구와 필요 시 보조 콘텐츠를 제공한다(PDF 262쪽).|
|기본값은 반복 행동의 계산 부담을 줄이는 방향으로 정한다.|훈련 수량은 1회 최대치 또는 보유 자원으로 가능한 최대치에 맞춰 동적으로 제시한다(PDF 263~264쪽).|
|저장 범위는 기기 단위/계정 단위의 경험과 비용을 비교해 정한다.|클라이언트 저장은 간단하지만 기기 변경 시 유지되지 않고, 서버 저장은 계정 유지 대신 비용이 늘어난다(PDF 264쪽).|
|갱신·숫자·시간·문자열 표기는 일관된 정책을 둔다.|랭킹/경매에는 정확한 시각, 친구 접속에는 상대 시간이 적합하며, 다국어 길이 초과 처리도 정의한다(PDF 264~265쪽).|

## 안티패턴

- IA 없이 화면만 그려 기능 연결·누락·반복 정보를 발견하지 못한다.
- 플로 차트에서 보상 없음, 레벨업 없음, 다음 단계 없음 같은 분기를 빼고 정상 사례만 작성한다.
- 와이어프레임을 완성 디자인처럼 만들며 기능 라벨과 반복 컴포넌트 규칙을 놓친다.
- ‘정렬한다’, ‘저장한다’라고만 쓰고 기본 기준·오름/내림·닫기·저장 위치를 비워 둔다.
- 결과 없음, 긴 문자열, 타임존, 정보 갱신 시점을 후반 구현 이슈로 넘긴다.

## 사례 재구성

**원문 사례 — 게임 클리어 결과 화면(PDF 253~255쪽).** IA는 클리어 정보·레벨/경험치·보상·재시도/목록/다음 단계의 계층과 연결을 보인다. 플로 차트는 승리→경험치/레벨업 조건→보상 조건→다음 스테이지 조건의 표시 순서를 정한다. 와이어프레임은 그 결과를 모듈과 버튼 영역으로 배치한다. 세 문서는 같은 화면을 정보 구조, 시간 분기, 공간 구조로 각각 검증한다.

**새 적용 예시 — 우편함 수령 화면.** IA에 우편 목록, 상세, 첨부 보상, 일괄 수령, 빈 상태를 둔다. 플로 차트는 `수령 가능 여부 → 보상 지급 성공/실패 → 배지 갱신 → 상세 닫기`를 분기한다. 와이어프레임은 목록·상세·수령 행동의 영역만 잡는다. 컴포넌트 표에는 기본 정렬, 수령 뒤 목록 갱신, 배지의 저장/갱신 기준, 결과 없음 문구를 적는다.

## 점검 항목

- [ ] IA에 상하위 계층, 그룹, 실제 이동 화살표, 확장 여지가 모두 있는가?
- [ ] 플로 차트가 사용자 행동뿐 아니라 모든 조건 분기와 출력 순서를 담는가?
- [ ] 와이어프레임이 이미지보다 역할·위치·반복성·라벨을 분명히 하는가?
- [ ] 모든 화면에 이름·역할·구성요소·배치 의도가 있는가?
- [ ] 드롭다운/정렬/필터에 기본값, 상태 표시, 닫기, 예외, 저장 위치가 있는가?
- [ ] 검색 결과 없음과 실패·빈 상태가 시스템 오류처럼 보이지 않는가?
- [ ] 갱신 주기·숫자/시간 형식·타임존·다국어 긴 문자열 정책을 정했는가?

## 용어 및 관련 장

- **IA(정보 구조도)**: 정보·콘텐츠의 배치와 탐색 구조를 시각화한 지도(PDF 252쪽).
- **UI 플로 차트**: 행동 뒤 화면 이동·선택·조건 분기를 정리한 흐름도(PDF 253쪽).
- **와이어프레임**: 디자인 전 기능 요소의 역할·위치·구조를 보는 기초 설계도(PDF 254쪽).

정보의 우선순위·깊이·표현은 [14장](ch14-visual-interaction.md), 입력·알림·탐색 컴포넌트의 상세 규칙은 [16장](ch16-ui-components.md), UX/UI의 역할 관계는 [13장](ch13-ux-ui-foundations.md)을 참조한다.
