# 19장: 시스템 기획서의 완성도를 결정하는 요소들

> **원문 범위:** PDF 326~339쪽 / 책 324~337쪽. 글자 10pt, 정보 밀도 60~70%, 복합 기능 약 40쪽·UX 중심 50쪽 이상은 이 책의 현장 권고와 사례이지 보편 의무값이 아니다(PDF 328~329쪽). AI가 만든 출석 보상 설득문 속 ‘일반적 데이터 패턴’, ‘도파민’, ‘LTV’도 검증된 사실·지표 정의로 승격하지 않는다(PDF 336~337쪽).

## 핵심 관점

문서 품질은 보기 좋은 장식이 아니라 **결정을 빠르게 하고 같은 구현을 재현하게 하는 전달 품질**이다. 좋은 시스템이라도 독자가 읽기 어렵거나 Why를 찾을 수 없으면 신뢰와 개발 속도를 잃는다(PDF 328쪽). 저자는 가독성, 필요한 만큼의 분량, 기능 단위 배치, Why→What→How의 논리 흐름을 품질 기준으로 제시하고, AI는 기획을 대체하는 작성기가 아니라 기획자의 사고를 확장·정리·검토·교정하는 보조자로 둔다(PDF 329~331쪽).

## 저자 절차와 판단 기준

### 1. 먼저 읽을 수 있게 만든다

본문을 촘촘하게 채우기보다 여백과 문단 구획을 두고, 배경과 글자 대비를 확보하며, 표·플로·와이어프레임은 글을 대신하는 장식이 아니라 이해가 필요한 지점의 보조 수단으로 쓴다(PDF 328쪽). 원문의 10pt 이하 지양 및 페이지 정보 밀도 60~70%는 특정 문서·도구·독자를 전제한 휴리스틱이다. 팀의 템플릿, 화면 크기, 접근성, 표 복잡도에 따라 달라질 수 있으므로, 숫자를 맞추기보다 실제 독자가 핵심 규칙과 예외를 빠르게 찾는지로 검증한다.

분량 역시 “짧을수록 좋다/길수록 성실하다”가 아니라 필수 정보를 빠짐없이 담고 중복을 없애는 문제다. 저자는 복합 기능에 약 40쪽, 이미지·와이어프레임 비중이 큰 UX 콘텐츠에는 50쪽 이상도 가능하다고 예시한다(PDF 329쪽). 이는 견적·품질의 절대 기준이 아니다. 기능 수, 상태 수, 예외, 플랫폼, 로컬라이징, 이미 존재하는 공통 명세를 기준으로 적정 범위를 판단한다.

### 2. 탐색 비용이 적은 구조로 배치한다

단일 기능은 개요→흐름 요약→상세 규칙→예외→데이터→UI→리소스/로컬라이징/로그 순서를 기본형으로 제시한다(PDF 329쪽). 복합 시스템에서는 UI를 모두 모은 뒤 테이블을 모두 모으는 식의 수직 분할보다, 하위 기능 하나 안에 규칙·예외·UI·데이터를 묶는다. 독자가 ‘이 기능의 버튼은 무엇을 읽는가?’를 찾기 위해 문서 전체를 왕복하지 않게 하기 위함이다.

### 3. AI에는 검토 가능한 산출물을 요청한다

- **브레인스토밍:** 막힌 일일 보상 설계에서 복수 콘셉트와 각 메커니즘·심리 가설·리스크를 받는다(PDF 331~332쪽). 결과는 후보이지 기획 확정안이 아니다.
- **구조화:** 섞인 메모를 의도, 트리 구조, 규칙, UX, 밸런스, 누락 데이터·로그 같은 섹션으로 재분류한다(PDF 333~335쪽). 원본 항목이 빠지거나 의미가 바뀌지 않았는지 사람이 대조한다.
- **논리 보강:** 주장·근거·기대 효과의 빈칸을 드러내도록 쓴다(PDF 335~337쪽). AI가 제시한 시장·심리·지표 주장은 출처, 실제 게임 데이터, 사용자 조사로 별도 검증한 뒤에만 문서 근거로 채택한다.
- **문장 교정:** 능동형, 한 문장 한 의미, 중복 제거를 요청한다(PDF 337~338쪽). 수치·조건·예외·용어는 축약 중 손실될 수 있으므로 교정 전후 의미를 검토한다.

## 주요 개념

- **가독성:** 글꼴 크기만이 아니라 대비, 여백, 정보 밀도, 시각 자료의 목적성까지 포함한다.
- **기능 단위 모듈:** 기능의 규칙·UI·데이터·예외를 함께 두어 탐색 비용을 줄이는 문서 단위다.
- **논리 전개:** Why(지금 필요한 이유)→What(만들 것)→How(플레이어·개발 관점의 작동)이다(PDF 330쪽).
- **AI 보조 범위:** 발상·구조·논리 초안·문장 정리다. 사실 검증, 목표 결정, 책임 있는 명세 승인까지 위임하는 보편 법칙은 아니다.

## 안티패턴과 대응

- **예쁜 문서 우선:** 어두운 저대비·과도한 그래픽이 명세를 가린다. 독해와 검색을 먼저 시험한다.
- **페이지 수 목표화:** 내용이 반복되거나 예외가 빠진다. 질문·상태·결정 기준으로 완결성을 판정한다.
- **복합 시스템의 수직 배치:** 한 기능을 이해하려 여러 장을 오간다. 기능 단위 모듈과 공통 참조로 재구성한다.
- **AI 답변을 근거로 인용:** 그럴듯한 심리학·시장·지표 문구를 사실처럼 싣지 않는다. 출처, 데이터 정의, 비교 기간을 확인하거나 가설로 표기한다.
- **교정 중 명세 손실:** 짧게 만들다 예외·단위·주체가 사라진다. diff 검토와 QA 관점 재독을 한다.

## 사례 재구성: 스킬트리 초안의 AI 보조 안전 적용

`레벨업 시 포인트 지급`, `선행 스킬`, `초기화 비용`, `전투 중 재배치 불가`가 뒤섞인 메모를 AI에 주고 섹션 분류와 누락 후보를 요청한다. 결과를 기획자가 원본과 비교해 ‘규칙’, ‘UI’, ‘밸런스 리스크’, ‘데이터’, ‘로그’로 배치한다. “초기화가 이탈을 줄인다” 같은 AI 문장은 가설 칸에만 두고, 실제 초기화 로그와 이탈 정의·비교 집단이 있어야 근거로 승격한다. 마지막에 “버튼이 작동되는 용도”를 “버튼을 누르면 초기화 확인 창을 연다”로 고치되, 발동 조건과 취소 결과가 남아 있는지 확인한다. 이는 원문의 구조화·설득 보강·문장 교정을 검증 가능한 작업으로 좁힌 예시다.

## 점검 항목

- [ ] 실제 독자가 목적, 정상 흐름, 예외, 데이터 출처를 빠르게 찾는가?
- [ ] 표·플로·와이어프레임마다 설명해야 할 질문이 분명한가?
- [ ] 페이지 수·글꼴·밀도 수치는 팀 맥락의 휴리스틱으로만 사용했는가?
- [ ] 복합 기능의 규칙·UI·데이터가 함께 탐색 가능한가?
- [ ] AI 산출물의 사실 주장, 수치, 인과, 용어 정의를 독립 자료로 확인했는가?
- [ ] 문장 축약 후 조건·단위·예외·책임 주체가 남았는가?
