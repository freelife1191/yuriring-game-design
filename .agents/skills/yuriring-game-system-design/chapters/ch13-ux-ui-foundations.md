# 13장 — UX/UI란 무엇인가?

> 출처: 정윤지(유리링), 『유리링의 실전 게임 시스템 기획』. 이 문서는 **PDF 쪽수**를 쓴다(책 인쇄 쪽수는 PDF보다 2쪽 작음). 핵심 근거: PDF 222~227쪽.

## 핵심 관점

UI는 플레이어가 보고 조작하는 화면·버튼·아이콘이고, UX는 그 이용 과정에서 생기는 편리함·혼란·만족·피로를 포함한 총체적 경험이다(PDF 224~225쪽). 둘은 구분해 설명할 수 있어도 실무에서는 한 흐름이다. 기능의 구조가 좋아도 UI가 보이지 않거나 이해되지 않으면 플레이어에게는 없는 기능과 같다(PDF 226쪽). 기능 목록을 넘어, 플레이어가 필요한 안내와 함께 의도한 행동을 수행하고 결과를 납득하는지도 점검한다. 이는 이 장의 경험 중심 관점을 적용한 검토 기준이다.

## 적용 절차 — 스킬의 재구성

아래 순서는 저자가 제시한 고정 절차가 아니라, 이 장의 개념과 사례를 작업에 적용하도록 정리한 방법이다. 기존 화면의 문제 진단에서 시작해도 된다.

1. **행동과 감정을 먼저 쓴다.** 화면별로 “무엇을 누르게/피하게 할 것인가, 어떤 감정으로 판단하게 할 것인가”를 정한다. 구매 확인처럼 신중한 결정을 유도해야 한다면 확인·취소의 위치, 간격, 시각적 우선순위를 함께 검토한다(PDF 224~225쪽).
2. **그 의도를 조작 가능한 UI로 번역한다.** UX의 ‘신중히 결정’은 버튼 강조, 간격, 위치, 확인 절차처럼 관찰 가능한 UI 명세가 되어야 한다(PDF 226쪽).
3. **불확실성을 검증한다.** 사람의 행동과 감정에는 정답을 단정하기 어렵다. 기획자의 직관에만 머무르지 말고 유사 게임 사례 조사와 A/B 테스트로 더 나은 선택을 찾는다(PDF 225쪽).
4. **시스템 규칙까지 되돌아본다.** UI가 복잡해져 시인성이 무너지면 화면 장식만 고치지 말고, 플레이어가 인식할 수 있는 규칙·동시 정보량인지 재검토한다(PDF 227쪽).

## 핵심 개념과 판단 규칙

|판단 규칙|적용 이유/근거|
|---|---|
|기능마다 플레이어의 첫 접점을 UI로 명시한다.|시스템은 UI를 통해 표현되고, UI가 어색하면 장점 대신 단점이 드러난다(PDF 226쪽).|
|구매·삭제처럼 실수 비용이 큰 행동은 결과를 먼저 이해시키고 결정을 유도한다.|확인 버튼의 강조·위치·간격도 UX 문제다(PDF 224~225쪽).|
|시각 디자인은 UX 결정의 구현으로 취급한다.|UI는 설계된 UX를 시각적으로 구현한 결과다(PDF 226쪽).|
|‘예쁘다’보다 ‘의도가 설명 없이 전달되는가’를 검토한다.|UI/UX는 기획 의도를 설명 없이 전달하는 수단이다(PDF 226쪽).|
|복잡한 성장·전투 규칙은 먼저 알아볼 수 있는 방식인지 시험한다.|직관적 UI가 아니면 잘 만든 시스템도 어렵게 느껴진다(PDF 226쪽).|
|시인성이 허용하는 범위를 게임 규칙에도 반영한다.|하스스톤의 필드 하수인 수 제한은 밸런스뿐 아니라 카드·효과 인식성에 기반했다(PDF 227쪽).|
|UX 결론은 가설로 적고 근거를 남긴다.|UX는 불확실성 안에서 더 나은 선택을 해 가는 영역이며 사례 조사·A/B 테스트가 필요하다(PDF 225쪽).|
|UI 산출물과 UX 산출물을 별도 완성으로 판정하지 않는다.|UI 없는 UX는 구체 구현이 없고, UX 없는 UI는 맥락이 없다(PDF 226쪽).|

## 안티패턴

- 시스템 기능을 만들었다는 이유로 발견·이해·오조작 방지 설계를 생략한다.
- 확인/취소의 의미, 우선순위, 간격을 아티스트의 미적 판단에만 맡긴다.
- ‘UI가 복잡하다’를 정보 디자인 문제로만 보고 과도한 규칙·동시 상태를 점검하지 않는다.
- 한 화면의 예쁨만 평가하고, 행동 뒤의 감정·판단 부담을 검증하지 않는다.

## 사례 재구성

**원문 사례 — 크리스탈 100개 구매 팝업(PDF 224~225쪽).** 저자는 ‘확인’ 클릭을 유도하려면 버튼의 좌우 위치·색 대비·간격을 어떻게 할지까지 UX가 결정해야 한다고 든다. UI 담당은 그 결정을 색, 테두리, 폰트, 입체감으로 구현한다. 화면 요소와 행동 설계를 분리하지 않는 사례다.

**새 적용 예시 — 길드 해산 화면.** “길드 해산”을 단순 빨간 버튼으로 끝내지 않는다. 해산 뒤 사라지는 권한·가입 상태를 문장으로 알려 행동 결과를 먼저 이해시키고, 취소와 해산의 시각 우선순위를 의도에 맞게 정한다. 이후 오조작·되돌림 시도 같은 관찰값으로 문구와 확인 흐름을 검토한다. 이는 저자의 구매 팝업 원칙을 다른 고비용 행동에 적용한 예시다.

## 점검 항목

- [ ] 이 화면이 유도하거나 막아야 할 행동과 그 이유가 한 문장으로 적혀 있는가?
- [ ] 각 UX 의도가 버튼 위치·문구·간격·강조·확인 절차 중 어떤 UI 규칙으로 구현되는가?
- [ ] 플레이어가 기능의 존재와 다음 행동을 설명 없이 알아차리는가?
- [ ] 실수 비용이 큰 선택의 결과를 누르기 전에 이해할 수 있는가?
- [ ] 유사 사례 조사 또는 사용성/A-B 검증이 필요한 불확실성은 무엇인가?
- [ ] 화면이 복잡하다면 정보 표현 이전에 시스템 규칙·동시 노출량을 다시 검토했는가?

## 용어 및 관련 장

- **UX(User Experience)**: 시스템 이용 중 생기는 감정·태도·행동의 총체(PDF 224쪽).
- **UI(User Interface)**: 화면, 버튼, 아이콘처럼 사용자가 직접 상호작용하는 요소(PDF 225쪽).
- **시인성**: 플레이어가 필요한 정보와 행동을 알아볼 수 있는 정도.
