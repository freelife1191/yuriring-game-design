# 21장: 시스템 기획자 레벨 업

> **원문 범위:** 책 356–364쪽 / PDF 358–366쪽. 원문은 기획자를 구조·관계·흐름을 설계하는 사람으로 정의하고, 아래 역량을 실무 훈련 기준으로 제시한다. 원신·랜덤 상점·파견 사례를 특정 게임 구현을 그대로 복제하라는 처방이 아니라 분석 관점을 보이는 사례로 읽는 것은 스킬 해석이다.

## 핵심 관점

좋은 아이디어는 시작일 뿐이다. 시스템 기획 역량을 아이디어를 조건·입력·처리·출력의 작동 구조로 바꾸고, 기존 루프·경제·UI·운영에 미칠 영향을 예측하며, 다른 직군이 한 뜻으로 구현하도록 명세하는 능력으로 요약한 것은 이 장을 묶은 스킬 정리다. 저자는 시스템 기획자에게 기술적·논리적 사고력, 사용자 관점의 UX 감각, 타 직군과의 커뮤니케이션 능력, 전체 게임 구조를 조망하는 넓은 시야가 필수라고 한다. 기획자는 “왜 필요한가, 플레이어는 왜 하는가, 추가하면 기존 흐름은 어떻게 바뀌는가”를 반복해 의심하고 답으로 남긴다(책 358쪽 / PDF 360쪽).

## 저자 절차와 판단 기준

### 1. 모든 기능을 조건 → 입력 → 처리 → 출력으로 설명한다

저자는 실무에서 자주 보는 나쁜 기획서가 기능을 단락으로만 설명해 누가·언제·어디서·무엇을·어떻게 트리거하는지 불명확하다고 진단한다(책 359쪽 / PDF 361쪽). 원문의 우편 보상 수령 사례는 미수령 메일이라는 조건, 버튼 클릭이라는 입력, 수령 여부·유효기간·인벤토리·최대 보유량 검사와 지급이라는 처리, 연출과 목록 제거라는 출력을 분리한다(책 359쪽 / PDF 361쪽). 원문은 이 틀을 기획서·회의·리뷰·개발 소통에 쓰라고 한다. 이를 플로·QA 케이스까지 넓혀 쓰고, 기능을 쓰기 전에 각 칸이 비어 있지 않은지 확인한다는 점검은 스킬 정리다.

### 2. 레퍼런스를 표면 기능이 아니라 역할로 분해한다

저자는 실무에서 요구되는 창의성이 무에서 유를 만드는 발상이 아니라 기존 시스템을 정확히 해석하고 맥락에 맞게 응용해 게임 구조에 맞게 재조립하는 능력이라고 한다(책 359쪽 / PDF 361쪽).

원신의 레진을 예로 들어, 저자는 사용 경로, UX(실시간 충전·저장/보충), 소모 시점, 최대치, 반복 콘텐츠와 성장 재화에 대한 역할, 플레이어의 관리 전략을 나누어 관찰한다(책 360–361쪽 / PDF 362–363쪽). 원문은 이런 분석이 가능한 사람은 '이 시스템이 왜 이런 형태로 만들어졌는가', '어떤 콘텐츠 흐름을 통제하기 위한 장치인가', '운영 측면에서 어떤 선택을 의도하는가'까지 관찰하고 추론할 수 있다고 한다(책 361쪽 / PDF 363쪽). 원문은 레진이 반복 콘텐츠 피로도 조절과 과금 유도 흐름에까지 영향을 주고, 콘텐츠가 적은 시기에도 '일정 시간 플레이 후 종료'라는 사용 패턴을 유지하게 한다고 분석한다(책 360–361쪽 / PDF 362–363쪽). 원문의 레진 분석은 구체적이다. 레진은 실시간 누적 충전이고 사용 여부는 플레이어가 고르며, 콘텐츠 입장 시점이 아니라 보상을 고르는 순간에 소모되게 해 자유도와 보상량 제한을 함께 유지한다. 충전 시간·보유 최대치·저장 최대치로 운영 리듬을 조절하고, 보스·던전·재료 파밍의 1일 기대 플레이 타임을 설계하는 기준이 되며, 무제한 파밍을 막으면서 성장 재화 루프를 조절한다. 언제 쓰고 얼마나 모을지 관리하는 것 자체가 전략 플레이 요소가 된다(책 360–361쪽 / PDF 362–363쪽). 이런 관찰을 쌓으면 패턴 라이브러리가 생기고, 바닥부터 설계하는 시간을 줄이고 플레이어에게 익숙하면서 완성도 높은 구조를 빠르게 만들 수 있다(책 361쪽 / PDF 363쪽). 관찰 결과를 복제품이 아니라 새 프로젝트의 제약과 타깃에 맞춰 재조합한다는 강조는 스킬 해석이다.

### 3. 새 기능 전 영향도를 시뮬레이션한다

장비 조각 성장 기능을 추가하기 전, 원문은 네 가지 충돌 영역을 검토한다. 기존 성장 루프와의 역할 충돌(하루에 수행할 수 있는 성장 콘텐츠의 양은 제한되어 있어, 이미 하루 루틴이 묶인 상황에서 파밍 루프를 더하면 피로도가 급증하고 '뭘 먼저 해야 하지?'라는 혼란 속에 특정 콘텐츠를 외면할 수 있다), 재화 문제(기존 재화를 공유하면 성장 우선순위 판단이 복잡해지고 경제가 흔들릴 수 있으며, 새 전용 재화를 도입하면 관리할 재화가 늘어 진입 장벽이 높아진다), 기존 강화 UI·인벤토리와의 충돌(기존 버튼 구성에 억지로 추가하거나 별도 탭을 만들면 UX가 분산된다), 루프 과포화다. 루프 과포화는 플레이어가 루틴을 줄이는 방향으로 최적화하는 '스킵 루프'나 신규 진입 장벽 상승으로 이어진다. 저자는 이런 영향을 미리 자문하고 시뮬레이션하라고 권하며, 이 역량이 부족하면 설계가 계속 땜질되어 나중에는 손대기 어려울 만큼 복잡해질 수 있다고 한다(책 361–362쪽 / PDF 363–364쪽). 아래 네 단계는 스킬이 이 사례에서 정리한 점검 순서이며 저자 절차가 아니다. (1) 영향받는 콘텐츠·재화·상태·화면·로그를 목록화하고, (2) 각 항목의 중복·대체·경쟁 관계를 적고, (3) 하루 루틴과 신규/기존 이용자 시나리오를 따라가며, (4) 제거·통합·단계 공개·보완 UX 중 대안을 비교한다. 목표는 기능 하나를 추가하는 것이 아니라 기존 경험을 지키며 구조를 확장하는 것이다.

### 4. 행동 뒤의 시간·기대·부담을 관찰한다

파견 미션은 보상 지급 기능처럼 보여도, 원문 사례에서는 접속 직후 수령과 재파견, 짧은 미션의 남은 시간이 추가 행동을 유도하는 일일 루틴 장치다. 오늘 할 일을 다 마쳤어도 '10분만 기다리면 다시 파견할 수 있는데…' 하며 플레이가 이어지고, 기획자가 이런 흐름을 의도하지 못하면 플레이 흐름이 끊기거나 타이밍이 어긋나 접속 유도 흐름이 무너질 수 있다(책 362–363쪽 / PDF 364–365쪽). 원문은 직접 플레이 경험을 분석하며 '내가 왜 이 타이밍에 이 행동을 했는가', '이 시스템이 나의 어떤 심리를 자극해 어떤 행동을 유도했는가', '이 기능을 기분 좋게 느꼈던 이유는 뭘까'를 스스로 관찰하는 훈련을 권한다(책 363쪽 / PDF 365쪽). 이 관찰로 의도한 경험과 실제 부담·혼란이 맞는지 추론한다는 해석은 스킬 정리다.

### 5. 모호한 자연어를 테스트 가능한 문장으로 바꾼다

랜덤 상점 사례에서 ‘랜덤 품목 등장’은 전 플레이어 공통인지 개인별인지, 슬롯 수도 랜덤인지가 빠져, 개발은 전 플레이어 일괄 갱신으로 구현해 구현 후 테스트 단계에서 전면 수정이 필요했고, QA는 품목 개수도 랜덤이라고 해석해 테스트 기준이 어긋났다(책 363–364쪽 / PDF 365–366쪽). 저자는 직군별로 어떤 정보가 필요한지 의식하며 쓰고, 문서를 완성한 뒤 '이걸 프로그래머, 아티스트, QA 담당자가 보고도 오해 없이 작업할 수 있을까?'를 반복해 자문하라고 한다(책 364쪽 / PDF 366쪽). 명세에 주체, 범위, 시점, 고정/변동 값, 정렬·동점, 실패·예외를 적는다는 목록은 스킬 정리다. 예: “매일 04:00 서버 기준으로 **플레이어별** 목록의 **상품 ID만** 갱신하며 슬롯 수 6개는 고정”처럼 검증 가능한 문장으로 쓴다. 이는 원문 사례를 바탕으로 한 새 문장 예시다.

### 6. 이상안보다 가능한 핵심을 우선한다

원문은 실무에서는 '더 나은 방향'보다 먼저 '지금 가능한 방향'을 찾아야 하며, 이론적으로 멋진 기획도 실제 일정에 맞지 않으면 무용지물이라고 한다(책 364쪽 / PDF 366쪽). 원문 예처럼 신규 이벤트의 개발 시간이 2주뿐이라면 신규 대형 시스템보다 기존 UI·테이블 재사용, 필수 기능 우선, 보조 기능의 다음 패치 이관을 검토한다(책 364쪽 / PDF 366쪽). 버튼 하나도 텍스트 표시인지 서버 조건·상태 저장·연출을 포함하는지에 따라 비용이 다르며, 원문은 기획자의 말 한 줄이 프로그래머에게는 하루짜리 작업이 될 수 있으므로 자신이 기획한 기능이 구현되는 과정을 최대한 많이 지켜보라고 한다(책 364쪽 / PDF 366쪽). 원문은 기능 구현에 걸린 시간과 지연 이유를 꾸준히 정리해 두면 이후 유사 기능 설계의 참조 기준이 되고, 클라이언트·서버 구조의 기초를 이해하면 기획서의 깊이와 설득력도 올라간다고 한다(책 364쪽 / PDF 366쪽). 이를 일정 추정 감각의 교정으로 쓰는 것은 스킬 해석이다.

## 주요 개념

- **논리적 구조화:** 조건·입력·처리·출력으로 설명 가능한 설계 언어.
- **패턴 라이브러리:** 레퍼런스의 목적·제약·UX·운영 역할을 분해해 축적한 재사용 가능한 관찰 기록.
- **영향도:** 기능 하나가 플레이 루프, 재화, 밸런스, UI, 유지보수, 신규 진입에 주는 연쇄 변화.
- **심리 추론:** 플레이어의 시간 감각, 보상 기대, 루틴 종결을 행동 관찰로 해석하는 일. 선택 부담은 스킬이 덧붙인 관찰 항목이다.
- **구현 가능성:** 일정·리소스·기존 자산·상태 저장·서버 조건까지 고려한 범위 판단.

## 안티패턴과 대응

> 이 절은 원문의 기준을 실패 사례로 정리한 스킬 정리다. `책 X쪽 / PDF Y쪽`이 붙은 항목만 그 쪽에 원문 근거가 있고, 나머지는 저자의 말로 인용하지 않는다.

- **아이디어를 설계로 착각:** 동작 흐름·실현 가능성·연동 영향이 없으면 제안이다. 구조와 예외로 내린다.
- **레퍼런스 외형 복사:** UI나 수치가 아니라 대상 게임에서의 역할·제약·보완책을 분석한다.
- **고립 기능 설계:** 재화·루프·화면·신규 유저 경로를 영향도 표로 먼저 점검한다.
- **모호한 형용사:** ‘랜덤’, ‘적절히’, ‘필요 시’ 대신 조건·주체·범위·상태로 쓴다.
- **일정을 희망으로 추정:** 핵심과 옵션을 나누고 실제 구현 이력으로 비용 가정을 갱신한다.

## 사례 재구성: 신규 ‘장비 조각’ 기능의 사전 리뷰

이 풀이는 스킬이 만든 재구성이며, 책에는 3절의 충돌 영역 검토만 있다.

조건·입력·처리·출력으로 보면, 조건은 조각 보유와 대상 장비의 해금, 입력은 강화 선택, 처리는 재화·조각 차감과 상한 검사, 출력은 단계 상승·스탯 반영·로그다. 다음으로 기존 유물 파밍·스킬 강화와 하루 자원 경쟁, 골드 공유 시 경제 압박, 전용 재화 도입 시 복잡도, 장비 화면에 둘 위치, 신규 유저의 진입 시점을 검토한다. 한 레퍼런스의 ‘파밍 재화’ 화면을 그대로 쓰지 않고, 해당 게임의 일일 루프와 현재 UI에 맞는 접근을 고른다. 출시 일정이 짧다면 1차에는 기존 강화 화면과 재화를 활용하고, 전용 조각·세트 보너스는 후속으로 분리한다. 이 과정에서 어떤 선택이 플레이어에게 새 판단을 주는지와 어떤 선택이 피로만 늘리는지를 플레이 테스트로 확인한다.

- [ ] 플레이어 행동의 시간·기대·부담을 실제 관찰이나 테스트로 확인하는가?
