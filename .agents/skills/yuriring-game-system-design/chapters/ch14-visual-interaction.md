# 14장 — UX/UI 기획을 위한 구성 요소와 표현 기법

> 출처: 정윤지(유리링), 『유리링의 실전 게임 시스템 기획』. 위치는 `책 인쇄 쪽 / PDF 쪽`으로 함께 적는다(이 책은 PDF 쪽 = 인쇄 쪽 + 2). 핵심 근거: 책 226–247쪽 / PDF 228–249쪽.

## 핵심 관점

레이아웃은 예쁜 배치가 아니라, 플레이어의 몰입과 조작을 위해 **무엇을 담고 어디에 둘지** 결정하는 전략이다(책 228쪽 / PDF 230쪽). 정보 우선순위는 절대적 중요도가 아니라 현재 맥락에서 필요한 정도로 정한다(책 229쪽 / PDF 231쪽). 접근 단계, 입력 결과의 예측 가능성, 크기·색상·메타포·연출도 같은 목적에 맞춰 정하므로 화면 설계는 정보량, 시선, 손의 동선, 감정의 흐름을 함께 다루는 일이라는 것은 14장을 묶은 스킬 정리다.

## 적용 절차 — 스킬의 재구성

아래 다섯 단계는 저자의 고정 절차가 아니라 14.1–14.5 절(레이아웃, 깊이와 상호 작용, 크기와 색상, 메타포, 스타일과 연출)을 작업 순서로 정리한 것이다. 단계 문장은 스킬 정리이고, 각 단계 끝의 '참고 원문 절'은 그 단계가 참고한 원문 범위다. 책의 말로 인용할 때는 아래 '핵심 판단 규칙'이나 원문 사례 문장의 쪽을 쓴다.

1. **현재 맥락의 필수 정보를 선별한다.** 장르·세션·기기에 따라 시야를 우선할지 상태 정보를 우선할지 결정하고, 고정 노출 대신 필요 시 열어 보는 정보도 둔다(참고 원문 절: 책 228–231쪽 / PDF 230–233쪽).
2. **시선과 조작 빈도로 영역을 배정한다.** 중심은 플레이·핵심 정보, 상단은 자주 보는 상태, 하단은 즉시 조작에 쓰는 식으로 배치하되 장르와 플랫폼에 맞춘다(참고 원문 절: 책 232–234쪽 / PDF 234–236쪽).
3. **깊이와 밀도를 함께 조정한다.** 자주 쓰는 기능은 1~2단계 안에 두고, 드문 세부 정보는 탭·펼침으로 분리한다. 한 화면 과밀과 과도한 이동 사이에서 사용 빈도·시점을 기준으로 절충한다(참고 원문 절: 책 235–236쪽 / PDF 237–238쪽).
4. **입력 뒤 결과를 말해 준다.** 명확한 라벨, 취소/확인의 분리, 즉각 피드백, 모바일 터치 동선을 설계한다(참고 원문 절: 책 237–238쪽 / PDF 239–240쪽).
5. **시각 언어와 감정 연출을 결합한다.** 크기·색은 우선순위와 위험을 전달하고, 친숙한 메타포는 학습 비용을 줄이며, 스타일·애니메이션·사운드는 세계관과 감정을 전달한다(참고 원문 절: 책 239–247쪽 / PDF 241–249쪽).

## 핵심 판단 규칙

|판단 규칙|조건·방법·이유|
|---|---|
|정보 노출 순서는 현재 필요한가로 정한다.|FPS는 시야를 위해 최소 정보, 수집형 RPG는 상태 정보를 더 많이 보일 수 있다(책 228–229쪽 / PDF 230–231쪽). 모바일은 화면이 작으므로 필수 정보 외의 요소는 최대한 숨기거나 축소한다(책 228쪽 / PDF 230쪽).|
|로비 구성은 장르의 세션과 자주 쓰는 행동으로 정한다.|원문은 짧은 세션의 모바일 캐주얼 디펜스 로비는 화면 중심을 비우고 최소한의 버튼만 좌우에 두고, 캐릭터 관리·전투 입장·이벤트가 많은 모바일 수집형 RPG 로비는 상단 유저 정보·오른쪽 메뉴·하단 전투 버튼으로 구성한 사례를 대조한다(책 229–230쪽 / PDF 231–232쪽). 호러 게임 '데드 스페이스'는 몰입을 위해 인터페이스를 없애고 체력 같은 정보를 캐릭터 장비 같은 사물로 보여 준다(책 231쪽 / PDF 233쪽).|
|중앙은 플레이를 가리지 않게 남긴다.|MMORPG HUD는 중앙 시야를 확보하고 좌우에 상황 인식·즉시 조작을 분산한다(책 230–231쪽 / PDF 232–233쪽).|
|자주 보는 정보는 잘 보이는 곳, 자주 누르는 것은 가까운 곳에 둔다.|원문의 인터페이스 배치 5대 원칙은 가시성(자주 볼 정보를 가장 잘 보이는 곳), 확장성(새 UI가 추가돼도 레이아웃이 무너지지 않게), 일관성(같은 기능은 같은 위치), 가독성(작은 글자·과도한 정보로 시각 피로를 주지 않게), 효율성(조작·시선 동선 가까이)이다(책 232쪽 / PDF 234쪽).|
|시선 흐름과 영역 성격으로 배치한다.|플레이어의 시선은 보통 중심 → 상단 → 좌측 → 우측 → 하단 순으로 움직인다. 좌측은 알림·퀘스트 같은 흐름 안내, 우측은 장비·덱·설정처럼 즉각 반응이 필요 없는 정보, 하단은 버튼·메뉴·채팅처럼 조작이 필요한 인터페이스에 적합하다(책 232–233쪽 / PDF 234–235쪽). 원문의 영역 그림과 추천 표는 Bottom Right 등 일부 영역 설명이 조금씩 다르므로 세부 배치는 원문 그림을 함께 보도록 안내한다. 원문 MMORPG HUD 사례(책 231쪽 / PDF 233쪽)는 우측에 즉시 조작을 두고, 일반 영역 설명(책 233쪽 / PDF 235쪽)은 우측을 즉각 반응이 필요 없는 정보 영역으로 쓴다. 실시간 전투 HUD와 일반 화면을 구분해 인용한다는 것은 스킬 정리다.|
|PC 구조를 모바일로 옮길 때는 엄지 조작을 기준으로 재해석한다.|'리그 오브 레전드: 와일드 리프트'는 왼쪽 하단 이동 패드와 오른쪽 하단 스킬·아이템 버튼으로 조작을 나누고, 미니맵·팀원 상태 같은 정보 HUD는 상단·왼쪽에 둔다(책 233쪽 / PDF 235쪽).|
|동일 기능은 동일 위치에 둔다.|원문은 일관성을 '동일한 기능은 동일한 위치에 유지'하는 배치 원칙으로 든다(책 232쪽 / PDF 234쪽). 탐색·학습 비용을 낮춘다는 이유는 스킬 해석이다.|
|자주 쓰는 기능은 1~2단계 안에 둔다.|최소 조작으로 최대 결과를 얻도록 하라는 원칙이다(책 235쪽 / PDF 237쪽).|
|세부 정보는 요약 뒤 펼침으로 제공한다.|과밀과 깊이의 트레이드오프를 사용 빈도·시점으로 해결한다(책 236쪽 / PDF 238쪽). 원문은 중요한 정보를 상위 레벨에 두는 정보 계층화, 헤더·탭·아이콘 강조·진행 바로 현재 위치를 시각화하기, 필터를 열기 전까지는 단순 리스트로 두는 동적 밀도를 든다(책 235–236쪽 / PDF 237–238쪽).|
|버튼은 결과를 가리키는 언어를 쓴다.|원문은 취소/확인을 분리하고, 실수로 누르기 쉬운 행동은 버튼 간격을 넓히거나 이중 확인 팝업을 두며, 설정은 즉시 반영되는 반응을 주라고 한다(책 237쪽 / PDF 239쪽). ‘취소/확인’보다 ‘유지/등록 취소’가 결과를 예측하게 하고, 토글은 ON 표시가 현재 상태인지 누르면 켜지는지 헷갈리기 쉬우며, '스킬 연출 끄기'처럼 라벨 자체가 부정형이면 켜는지 끄는지 더 헷갈린다(책 238쪽 / PDF 240쪽). 모바일에서는 손가락이 화면을 가리지 않게 하단 오른쪽에 중요한 조작을 두는 것이 일반적이다(책 237–238쪽 / PDF 239–240쪽).|
|크기와 색으로 우선순위를 표현한다.|중요한 요소일수록 크게, 상호 작용 버튼은 일정 크기 이상을 확보한다. 저자는 모바일에서 최소 40px 이상을 확보하지 않으면 오입력이 빈번하다고 쓴다(책 239쪽 / PDF 241쪽). 이 값은 저자의 서술이며 프로젝트 기본 규격으로 그대로 옮기지 않는다. 다국어 UI는 언어별 텍스트 길이를 고려해 버튼 크기를 잡는다(책 240쪽 / PDF 242쪽). 색은 종류를 최소화하고 대비를 확보하며, 게임 테마 팔레트와 조화시키고 문화적 맥락을 고려한다(한국·일본에서 붉은색은 희망·긍정의 의미이기도 하다)(책 240쪽 / PDF 242쪽). 원문 사례로 붉은색을 '스타워즈: 갤럭시 오브 히어로즈'는 디버프에, '프린세스 커넥트: 리다이브'는 버프에 쓴다(책 241쪽 / PDF 243쪽).|
|메타포는 친숙한 대상일 때 쓴다.|가방=인벤토리, 톱니=설정처럼 설명 없이 기능을 유추하게 한다(책 242–243쪽 / PDF 244–245쪽).|
|스타일은 장르·테마와 통일하고, 앱 스타일을 그대로 쓰지 않는다.|장르·테마와 시각적 아이덴티티를 통일하고 그래픽 톤을 일관되게 유지한다. 저자는 게임은 몰입과 감성의 매체이므로 편리함만 추구하는 앱 스타일은 감흥이 없고, 불편할 수 있어도 감성적으로 납득되는 스타일이 때로는 더 효과적이라고 한다. 사례는 '페르소나 5'다(책 244–246쪽 / PDF 246–248쪽).|
|연출은 목적을 가져야 한다.|원문의 연출 이유는 즉각적인 피드백, 시각적 계층 구조, 기대감·긴장감, 시각적 만족감이다(책 246쪽 / PDF 248쪽). 카드 뽑기 연출은 초기 화면 → 뽑기 시작 → 카드 미리 보기 → 카드 공개 → 보상 정리의 장면마다 설명과 목적을 적은 스토리보드로 설계한다(책 247쪽 / PDF 249쪽).|

## 안티패턴

> 이 절은 원문의 기준을 실패 사례로 정리한 스킬 정리다. `책 X쪽 / PDF Y쪽`이 붙은 항목만 그 쪽에 원문 근거가 있고, 나머지는 저자의 말로 인용하지 않는다.

- 모든 정보를 고정 노출해 체력·핵심 상태조차 복잡한 화면 속에 묻히게 한다.
- PC용 조작 밀도를 모바일에 이식해 손가락이 버튼·시야를 가리게 한다.
- 질문을 취소하는지 행동을 취소하는지 모호한 ‘취소/확인’ 버튼을 쓴다.
- 강조색을 너무 많이 써서 어떤 행동이 핵심인지 사라지게 하거나, 문화적 맥락을 고려하지 않고 색의 의미를 고정한다.
- 세계관과 무관한 앱형 UI를 그대로 가져오거나, 감정을 만들지 않는 장식적 연출을 더한다.

## 사례 재구성

**원문 사례 — 거래소 등록 취소 팝업(책 237–238쪽 / PDF 239–240쪽).** ‘취소/확인’은 질문을 취소하는지 거래소 등록을 취소하는지 모호하다. 저자는 `유지`와 `등록 취소`처럼 결과를 직접 라벨링하고, 취소 뒤 물품이 인벤토리로 돌아감을 함께 보여 주는 방식을 제시한다.

**새 적용 예시 — 전투 중 장비 프리셋 전환.** 전투 HUD에는 즉시 필요한 스킬만 두고, 프리셋 상세 옵션은 펼침으로 분리한다. 전환 버튼은 ‘프리셋 2 적용’처럼 결과를 명시하고 적용 뒤 활성 상태·짧은 피드백을 준다. 이는 깊이/밀도 절충과 예측 가능한 상호작용을 함께 적용한 예시다.

## 점검 항목

> 스킬이 만든 점검 목록이다. 근거는 위 절들의 쪽 표기를 따른다.

- [ ] 이 화면에서 현재 꼭 보여야 하는 정보와 필요할 때만 열 정보가 구분됐는가?
- [ ] 중심 시야, 시선 흐름, 손의 조작 영역을 장르·기기에 맞춰 배정했는가?
- [ ] 자주 쓰는 기능은 1~2단계 안에 있고, 드문 기능은 요약/탭/펼침으로 분리됐는가?
- [ ] 버튼 라벨만 읽어도 실행 결과와 되돌림 가능성을 알 수 있는가?
- [ ] 중요도와 실수 비용이 크기·간격·색 대비에 반영됐는가?
- [ ] 아이콘 메타포는 대상 이용자에게 친숙하며 텍스트가 필요한 곳을 대신하지 않는가?
- [ ] 연출은 피드백·시선 유도·기대감 중 명확한 목적을 갖는가?

## 용어 및 관련 장

- **UI 깊이**: 원하는 정보·기능에 도달하기까지 필요한 조작/화면 이동 단계(책 235쪽 / PDF 237쪽).
- **메타포**: 익숙한 현실 사물·개념을 빌려 기능을 언어 없이 전달하는 표현(책 242쪽 / PDF 244쪽).
- **HUD**: 플레이 중 필요한 상태·조작을 화면 위에 제공하는 인터페이스.

실제 구조 문서는 [15장 UX/UI 설계](ch15-ux-ui-design.md)에서 IA·플로·와이어프레임으로 고정하고, 세부 컴포넌트는 [16장](ch16-ui-components.md) 규칙으로 명세한다. 기획 의도와 UX/UI의 관계는 [13장](ch13-ux-ui-foundations.md)을 참조한다.

## 원문/OCR 한계

배치 영역 표와 사례 설명을 텍스트 기준으로 요약했다. 도판의 실제 좌표·색상값·크기는 추출 텍스트로 검증할 수 없으므로 수치 규격으로 전환하지 않았다.
