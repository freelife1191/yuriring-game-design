# 14장 — UX/UI 기획을 위한 구성 요소와 표현 기법

> 출처: 정윤지(유리링), 『유리링의 실전 게임 시스템 기획』. 이 문서는 **PDF 쪽수**를 쓴다(책 인쇄 쪽수는 PDF보다 2쪽 작음). 핵심 근거: PDF 228~249쪽.

## 핵심 관점

레이아웃은 예쁜 배치가 아니라, 플레이어의 몰입과 조작을 위해 **무엇을 담고 어디에 둘지** 결정하는 전략이다(PDF 230쪽). 정보 우선순위는 절대적 중요도가 아니라 현재 맥락에서 필요한 정도로 정한다(PDF 231쪽). 이어서 접근 단계, 입력 결과의 예측 가능성, 크기·색상·메타포·연출이 같은 목적을 수행한다. 즉 화면 설계는 정보량, 시선, 손의 동선, 감정의 흐름을 함께 다루는 일이다.

## 저자 프레임워크/절차

1. **현재 맥락의 필수 정보를 선별한다.** 장르·세션·기기에 따라 시야를 우선할지 상태 정보를 우선할지 결정하고, 고정 노출 대신 필요 시 열어 보는 정보도 둔다(PDF 230~233쪽).
2. **시선과 조작 빈도로 영역을 배정한다.** 중심은 플레이·핵심 정보, 상단은 자주 보는 상태, 하단은 즉시 조작에 쓰는 식으로 배치하되 장르와 플랫폼에 맞춘다(PDF 234~236쪽).
3. **깊이와 밀도를 함께 조정한다.** 자주 쓰는 기능은 1~2단계 안에 두고, 드문 세부 정보는 탭·펼침으로 분리한다. 한 화면 과밀과 과도한 이동 사이에서 사용 빈도·시점을 기준으로 절충한다(PDF 237~238쪽).
4. **입력 뒤 결과를 말해 준다.** 명확한 라벨, 취소/확인의 분리, 즉각 피드백, 모바일 터치 동선을 설계한다(PDF 239~240쪽).
5. **시각 언어와 감정 연출을 결합한다.** 크기·색은 우선순위와 위험을 전달하고, 친숙한 메타포는 학습 비용을 줄이며, 스타일·애니메이션·사운드는 세계관과 감정을 전달한다(PDF 241~249쪽).

## 핵심 판단 규칙

|판단 규칙|조건·방법·이유|
|---|---|
|정보 노출 순서는 현재 필요한가로 정한다.|FPS는 시야를 위해 최소 정보, 수집형 RPG는 상태 정보를 더 많이 보일 수 있다(PDF 230쪽).|
|중앙은 플레이를 가리지 않게 남긴다.|MMORPG HUD는 중앙 시야를 확보하고 좌우에 상황 인식·즉시 조작을 분산한다(PDF 232~233쪽).|
|자주 보는 정보는 잘 보이는 곳, 자주 누르는 것은 가까운 곳에 둔다.|가시성·효율성·시선 흐름이 배치 원칙이다(PDF 234~235쪽).|
|동일 기능은 동일 위치에 둔다.|일관성이 탐색과 학습 비용을 낮춘다(PDF 234쪽).|
|자주 쓰는 기능은 1~2단계 안에 둔다.|최소 조작으로 최대 결과를 얻도록 하라는 원칙이다(PDF 237쪽).|
|세부 정보는 요약 뒤 펼침으로 제공한다.|과밀과 깊이의 트레이드오프를 사용 빈도·시점으로 해결한다(PDF 238쪽).|
|버튼은 결과를 가리키는 언어를 쓴다.|‘취소/확인’보다 ‘유지/등록 취소’가 결과를 예측하게 한다(PDF 239~240쪽).|
|크기와 색으로 우선순위를 표현한다.|작은 모바일 버튼은 오입력 위험이 크고, 색 대비는 주요 행동과 위험을 구분한다(PDF 241~243쪽).|
|메타포는 친숙한 대상일 때 쓴다.|가방=인벤토리, 톱니=설정처럼 설명 없이 기능을 유추하게 한다(PDF 244~245쪽).|
|연출은 피드백·계층·기대감의 목적을 가져야 한다.|보상 공개나 클릭 반응은 이해와 감정적 보상을 동시에 만든다(PDF 248~249쪽).|

## 안티패턴

- 모든 정보를 고정 노출해 체력·핵심 상태조차 복잡한 화면 속에 묻히게 한다.
- PC용 조작 밀도를 모바일에 이식해 손가락이 버튼·시야를 가리게 한다.
- 질문을 취소하는지 행동을 취소하는지 모호한 ‘취소/확인’ 버튼을 쓴다.
- 강조색을 너무 많이 써서 어떤 행동이 핵심인지 사라지게 하거나, 문화적 맥락을 고려하지 않고 색의 의미를 고정한다.
- 세계관과 무관한 앱형 UI를 그대로 가져오거나, 감정을 만들지 않는 장식적 연출을 더한다.

## 사례 재구성

**원문 사례 — 거래소 등록 취소 팝업(PDF 239~240쪽).** ‘취소/확인’은 질문을 취소하는지 거래소 등록을 취소하는지 모호하다. 저자는 `유지`와 `등록 취소`처럼 결과를 직접 라벨링하고, 취소 뒤 물품이 인벤토리로 돌아감을 함께 보여 주는 방식을 제시한다.

**새 적용 예시 — 전투 중 장비 프리셋 전환.** 전투 HUD에는 즉시 필요한 스킬만 두고, 프리셋 상세 옵션은 펼침으로 분리한다. 전환 버튼은 ‘프리셋 2 적용’처럼 결과를 명시하고 적용 뒤 활성 상태·짧은 피드백을 준다. 이는 깊이/밀도 절충과 예측 가능한 상호작용을 함께 적용한 예시다.

## 점검 항목

- [ ] 이 화면에서 현재 꼭 보여야 하는 정보와 필요할 때만 열 정보가 구분됐는가?
- [ ] 중심 시야, 시선 흐름, 손의 조작 영역을 장르·기기에 맞춰 배정했는가?
- [ ] 자주 쓰는 기능은 1~2단계 안에 있고, 드문 기능은 요약/탭/펼침으로 분리됐는가?
- [ ] 버튼 라벨만 읽어도 실행 결과와 되돌림 가능성을 알 수 있는가?
- [ ] 중요도와 실수 비용이 크기·간격·색 대비에 반영됐는가?
- [ ] 아이콘 메타포는 대상 이용자에게 친숙하며 텍스트가 필요한 곳을 대신하지 않는가?
- [ ] 연출은 피드백·시선 유도·기대감 중 명확한 목적을 갖는가?

## 용어 및 관련 장

- **UI 깊이**: 원하는 정보·기능에 도달하기까지 필요한 조작/화면 이동 단계(PDF 237쪽).
- **메타포**: 익숙한 현실 사물·개념을 빌려 기능을 언어 없이 전달하는 표현(PDF 244쪽).
- **HUD**: 플레이 중 필요한 상태·조작을 화면 위에 제공하는 인터페이스.

실제 구조 문서는 [15장 UX/UI 설계](ch15-ux-ui-design.md)에서 IA·플로·와이어프레임으로 고정하고, 세부 컴포넌트는 [16장](ch16-ui-components.md) 규칙으로 명세한다. 기획 의도와 UX/UI의 관계는 [13장](ch13-ux-ui-foundations.md)을 참조한다.

## 원문/OCR 한계

배치 영역 표와 사례 설명을 텍스트 기준으로 요약했다. 도판의 실제 좌표·색상값·크기는 추출 텍스트로 검증할 수 없으므로 수치 규격으로 전환하지 않았다.
