# 참조 자료 구성과 원문 반영 검수

## 결론과 범위

기존 `chapters/` 21개와 용어·패턴·판단표는 이미 필요한 때 읽는 참조 자료였다. `references/`라는 폴더 이름의 부재는 내용 누락의 증거가 아니다. 21장의 핵심 구조·절차·판단 규칙·선별 사례를 원문 해당 장 텍스트와 대조한 결과, 재사용형 게임 시스템 기획 지식으로 전반적인 반영 수준은 적절했다. 두 판단 기준을 보완하고 구체적인 질문의 탐색 경로를 추가했다.

**모든 소절·문장·표·그림을 포함하거나 전수 검증했다는 뜻은 아니다.** 정확한 원문 칼럼명·수치·도판 배치가 필요한 질문에는 해당 원본 확인이 필요하다.

## 유지되는 참조 구조

- `SKILL.md`: 핵심 원칙과 21장·주제 색인, 자료 선택 지침.
- `chapters/`: 21개 장의 개념·절차·판단·사례·예외·출처.
- `references/index.md`: 26개 사례·질문 항목, 6개 장 연결 작업, UX/UI 세부 원문 위치.
- `glossary.md`: 주요 용어 39개.
- `patterns.md`: 실무 적용 패턴 8개.
- `cheatsheet.md`: 상황별 판단표.
- `source.json`: 원본 정보·쪽 범위·역대 검수 이력·한계.

루트 README와 가이드의 구성 설명을 함께 수정했다. 변환기는 제외 상태를 유지하며 게임 기획 스킬의 사용 의존성으로 추가하지 않았다. 고급 활용법의 기존 42개 프롬프트·21개 후속 요청은 변경하지 않았다.

- 루트 문서·스킬 자료·검수 보고서 35개에서 로컬 링크/앵커 **352개**, 깨진 링크 **0개**.
- 스킬 내부 Markdown 참조 **144개**가 모두 스킬 폴더 내부에 있음. 전체 폴더를 다른 임시 경로에 복사해도 참조 유지 확인. 파일 **28개**, 장 파일 **21개**.

- 기존 고급 활용법은 검토 시작 전과 바이트 내용이 동일함.
- 기본 변환기 패키지의 전체 테스트와 앱 런타임 테스트는 이 변경의 검증 범위가 아님.

## 독립 사용 테스트

평가 에이전트에는 스킬 경로와 현실적인 요청만 제공했다. 원본 PDF·기존 검수 결과·외부 검색을 사용하지 않고 스킬 내부 자료만 읽었다.

| 요청 | 실제 선택한 주요 장 | 확인한 판단과 한계 |
|---|---|---|
| 다국어 NPC 대사와 UI 문자열 | 10–12, 15 | 스트링·챕터·대사 행의 책임과 참조를 구분. 정확한 원문 전체 칼럼명은 스킬만으로 복원 불가라고 명시 |
| 모바일 아이템 수량 스테퍼 | 07, 15–16 | 범위·경계·보정·상태를 제안하되 기본 선택 수량은 미정으로 유지. 정적 제목·설명에 입력·저장 강제 안 함 |
| 자동 파견 캐릭터 선정 | 07, 09, 11, 15, 18 | 조건 점수 → 등급 → 레벨 → 고유 ID를 보존. 각 정렬 방향은 확정 불가로 유지 |

세 답변의 내용과 자료 선택은 적절했으나 초기 답변의 근거 링크가 존재하지 않는 `../repo/...` 경로여서 **전체 판정은 세 건 모두 부분 통과**였다. 참조 색인에 실제 읽은 경로를 인용하도록 명시한 뒤, 평가 에이전트가 답변의 판단·문구를 유지하면서 링크 12개만 실제 절대경로로 바로잡았다. 읽은 파일 기록도 보완했다. 수정 후 경로·의미 보존 검사에서 세 건 모두 통과했다. **새 독립 세션에서 답변 전체를 다시 생성한 테스트는 아니다.**

원본 결과는 `behavior/initial/`에, 수정된 답변과 읽은 파일 기록은 `behavior/`에 보존했다. 최초 답변의 깨진 링크는 실패 증거이므로 보존본에서 수정하지 않았다.
