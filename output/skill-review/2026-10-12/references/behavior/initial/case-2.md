# 요청 2 — 모바일 아이템 사용 수량 화면 명세

## 확정 가능한 기준과 미정 사항

보유 수량이 12이므로, 아이템을 최소 1개부터 선택해 사용하는 규칙이라면 스테퍼의 범위는 **1~12**, 단위는 **1**로 명세할 수 있다. 다만 기본 선택 수량은 아직 미정이므로 구현값을 확정해서는 안 된다. 책의 아이템 사용 스테퍼 사례는 “최솟값 1, 최댓값 보유 수량, 단위 1, 사용 가능한 최대치를 기본값”으로 든다([ch16](../repo/.agents/skills/yuriring-game-system-design/chapters/ch16-ui-components.md), PDF p.273–274). 이것은 사례의 기본값이므로, 이 화면에서 기본값을 12로 채택할지 1로 둘지는 아이템 소비 의도·오조작 위험을 보고 결정해야 한다.

## 화면/요소 명세

| 요소 | 역할과 표시 | 입력·상태 | 결과·오류·갱신 |
| --- | --- | --- | --- |
| 제목 | 아이템 사용 화면의 목적을 표시 | 정적 텍스트. 다국어라면 스트링 키와 긴 문구 처리 정책을 둔다 | 입력·저장 규칙을 강제할 요소는 아니다 |
| 설명 문구 | 사용할 아이템의 효과·대상 또는 주의사항을 전달 | 정적/동적 여부와 줄바꿈·긴 문구 처리를 명세 | 입력·저장 규칙을 강제할 요소는 아니다 |
| 현재 보유 수량 | 선택 가능한 상한 12를 보여 줌 | 사용 완료·보유량 변경 시 갱신 시점 명시 | 화면 표시와 실행 직전 수량이 다르면 실행 전 재검증 |
| `-` 버튼 | 선택 수량을 1만큼 감소 | 선택값이 1이면 Disabled; 플랫폼에서 지원하는 Default/Pressed/Disabled 상태를 구분 | Disabled 사유가 분명히 보이게 함 |
| `+` 버튼 | 선택 수량을 1만큼 증가 | 선택값이 12이면 Disabled | 12에서 더 누르지 못하게 함 |
| 직접 숫자 입력 | 원하는 정수 수량을 빠르게 지정 | 허용: 정수 1~12. 숫자 외·소수·0·음수·초과값의 보정/거부 정책을 정함 | 잘못된 값은 보정하고, 보유량 초과는 메시지로 안내하는 것이 원문 사례의 기준 |
| 선택 수량 표시 | 현재 유효 수량을 확인 | 기본값은 **미정**. 확정 전에는 기획 문서에 미정으로 표시 | 직접 입력·버튼 변경 뒤 같은 값을 즉시 반영 |
| 실행 버튼 | 유효한 선택 수량으로 사용 요청 | 유효 범위의 수량이 있을 때 활성. 미입력·유효하지 않은 값·실행 불가 상태면 Disabled 또는 실패 안내 정책을 명시 | 실행 직전에 보유 수량과 사용 가능 상태를 다시 확인하고, 성공/실패 뒤 수량·버튼 상태를 갱신 |

## 상태와 예외 흐름

```text
화면 진입 → 보유 수량 12 표시 → 기본 선택 수량 결정/표시
  → 수량 변경(+/-/직접 입력)
  → 1~12인가?
     ├─ 아니오 → 보정 또는 오류 안내(정책 미정) → 실행 비활성/재입력
     └─ 예 → 경계면 해당 +/- 비활성 → 실행 버튼 활성
  → 실행
  → 실행 직전 보유 수량·사용 가능 상태 재검증
     ├─ 실패 → 상태 유지와 이유 안내
     └─ 성공 → 사용 처리 → 보유 수량·선택 수량·버튼 상태 갱신
```

`+`의 상한 비활성화, 직접 입력 보정, 초과 메시지는 ch16의 원문 사례(PDF p.273–274)에 근거한다. 실행 직전 재검증과 실패 시 상태 보존·이유 안내는 [ch07](../repo/.agents/skills/yuriring-game-system-design/chapters/ch07-rule-components.md)의 규칙·예외 원칙(책 p.106–115 / PDF p.108–117)에 따른다. 화면명·역할·요소·배치 이유, 기본값·예외·갱신을 함께 써야 한다는 기준은 [ch15](../repo/.agents/skills/yuriring-game-system-design/chapters/ch15-ux-ui-design.md)의 PDF p.250–265에 근거한다.

## 결정이 필요한 사항

| 항목 | 선택지 | 영향 |
| --- | --- | --- |
| 기본 선택 수량 | 1 / 12(사용 가능 최대치) / 이전 선택 기억 | 1은 오사용 위험을 낮추고, 12는 반복 사용 입력을 줄인다. 이전값 저장은 기기·계정 단위와 초기화 시점이 필요하다. |
| 잘못된 직접 입력 처리 | 범위 안으로 자동 보정 / 입력 거부 후 오류 표시 | 자동 보정은 빠르지만 사용자가 변경 사실을 놓칠 수 있고, 거부는 의도를 더 명확히 보여 준다. |
| 실행 결과 통지 | 토스트 / 팝업·모달 / 화면 내 메시지 | 메시지 중요도와 조작 차단 여부에 맞춰 고른다([ch16], PDF p.280–283). |
