# 요청 3 — 자동 파견 캐릭터 선정과 통합 검토 순서

## 자동 선정 규칙

책의 파견 미션 사례에서 자동 배치는 **조건 점수 → 등급 → 레벨 → 캐릭터 고유 ID** 순으로 후보를 비교한다([ch18](../repo/.agents/skills/yuriring-game-system-design/chapters/ch18-document-workshop.md), PDF p.311 / 책 p.309). 이 순서는 수동 편성보다 항상 최적이 되도록 보장하지 않아, 플레이어가 직접 판단할 전략 여지를 남긴다는 설명도 함께 있다.

그러나 이 스킬 자료만으로는 각 기준의 **정렬 방향**을 확정할 수 없다. 예를 들어 조건 점수·등급·레벨이 높은 값 우선인지 낮은 값 우선인지, 고유 ID가 숫자/문자열일 때 어떤 방향으로 안정 정렬하는지는 명시돼 있지 않다. 따라서 “조건 점수 동점이면 등급, 다시 동점이면 레벨, 다시 동점이면 고유 ID”까지는 원문 근거로 확정할 수 있지만, 방향은 프로젝트 결정 항목으로 남겨야 한다.

## 규칙·데이터·UI를 함께 검토하는 권장 순서

1. **개요와 범위부터 고정한다.** 왜 자동 파견이 필요한지, 타깃, 파견의 전체 시나리오와 관련 시스템 경계를 한 문단·목록으로 합의한다. ch18은 개요 뒤에 목적·타깃·시나리오·구현 시스템을 놓는다(PDF p.304–307).
2. **규칙을 먼저 닫는다.** 후보 자격(이미 파견 중인지 등), 자동 선발의 입력, 위 4단계 우선순위, 파견 정원, 성공·실패 결과, 후보 없음·정원 미달·중도 복귀·동시 상태의 처리를 조건→입력→처리→결과→예외로 작성한다. ch18의 파견 사례와 [ch07](../repo/.agents/skills/yuriring-game-system-design/chapters/ch07-rule-components.md)의 규칙 분해(책 p.106–115 / PDF p.108–117)를 적용한다.
3. **규칙의 분기를 플로로 검증한다.** `자동 편성 요청 → 가능한 후보 필터 → 우선순위 비교 → 정원 충족? → 편성/실패 안내 → 실행 가능 상태`를 그리고, 후보 없음·동점·이미 파견됨·실행 직전 상태 변경의 종료 경로를 추가한다. [ch09](../repo/.agents/skills/yuriring-game-system-design/chapters/ch09-flowcharts.md)은 판단·처리·출력과 예외 분기를 흐름으로 검증하라고 한다(책 p.134–155 / PDF p.136–157).
4. **데이터가 규칙을 실행할 수 있는지 확인한다.** 미션에는 고유 ID·문자열 키·분류·등장 그룹/확률·기간·조건 유형/값·보상 ID/수량 같은 역할의 값이 필요하고, 캐릭터 쪽에는 고유 ID·조건 점수 계산에 필요한 속성·등급·레벨·파견 상태가 필요하다. 각 열에 타입·의미·단위·허용값·참조·소비처를 붙인다. ch18은 서버가 조건 배율과 최종 보상을 계산하는 사례를 든다(PDF p.311–313). 실제 서버/클라이언트 책임은 프로젝트의 권한·부정 조작·일관성 요구에 따라 정한다.
5. **UI를 상태 전이로 맞춘다.** 진입 → 대상 선택/자동 편성 → 조건 확인 → 편성 → 실행 → 진행 → 수령 → 다음 루프를 정의하고, 미배정·선택 중·진행·완료·후보 없음 상태별 표시, 버튼 활성 조건, 비활성 이유, 결과 갱신을 적는다(ch18, PDF p.313–324). 화면 구조는 [ch15](../repo/.agents/skills/yuriring-game-system-design/chapters/ch15-ux-ui-design.md)의 IA → UI 플로 → 와이어프레임 → 요소 행동 명세 순서로 보완한다(PDF p.250–265).
6. **가데이터와 교차 검증을 한다.** 같은 동점 후보, 등급만 다른 후보, 레벨만 다른 후보, 파견 중 후보, 후보 없음, 정원 미달의 입력을 만들어 규칙의 결과·데이터 조회·UI 표기가 같은 순서를 쓰는지 확인한다. ch11은 가데이터로 구조·참조·경계 조건을 검증하라고 한다(책 p.188–190 / PDF p.190–192).

## 동점과 정렬 방향의 결정표

| 항목 | 이 자료로 확정 가능 | 추가로 정할 것 |
| --- | --- | --- |
| 1차~4차 비교 항목 | 조건 점수 → 등급 → 레벨 → 캐릭터 고유 ID | 각 값의 산출/참조 방식 |
| 동점 처리 | 앞 기준이 같을 때 다음 기준으로 넘어감 | 네 기준도 같을 때의 안정성 규칙(고유 ID 유일성 전제 포함) |
| 정렬 방향 | 확정 불가 | 각 항목의 오름/내림, 등급의 서열 매핑, ID 비교 방식 |
| 자동 편성 실패 | 대상 가능 조건·실패 피드백이 필요 | 후보 없음/정원 미달 때 유지할 기존 편성, 안내 문구, 재시도 정책 |
