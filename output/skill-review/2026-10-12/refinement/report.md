# 검증 기반 보완과 재검수

앞선 [프롬프트 검사](../prompt-examples/report.md)와 [실제 CLI 호출·표본 검사](../host-smoke/report.md)에서 드러난 보완점을 스킬과 가이드에 반영했습니다. 데이터·QA 요청을 새 독립 평가자 2명에게 수행시켰고, 데이터 답변의 출처 구분을 한 차례 더 보완해 재검사했습니다.

| 표본 | 초기 판정 | 최종 판정 | 검사 범위 |
|---|---|---|---|
| 자동 편성 결과 데이터 | 부분 통과 | 통과 | 새 독립 평가 후 같은 평가자가 보완된 스킬로 전체 답변 재생성 |
| 출석 보상 메모 검토·QA | 통과 | 통과 | 새 독립 평가 |

> [!IMPORTANT]
> 이번 보완은 원문 지식의 재추출이 아닙니다. 업무상 중복 범위·QA 기대 결과 점검은 검증 기반 적용 지침으로 표시하며, 책의 직접 서술이나 저자의 별도 프레임워크로 인용하지 않습니다.

## 1. 검증 기록에서 반영한 개선

| 확인된 문제 | 반영한 내용 | 적용 위치 |
|---|---|---|
| 요청 1건과 선택 캐릭터 1명의 행 단위가 모호함 | 행 의미·기본 키·업무상 중복 금지 범위를 함께 점검 | SKILL.md, 데이터 패턴, 판단표 |
| 행 ID가 유일하면 업무상 중복도 막힌다고 오해할 수 있음 | 요청/회차 안의 중복과 전역 유일성을 구분하는 새 예시 | 데이터 패턴, README, 워크플로 |
| 미정 응답 정책 때문에 확정된 중복 지급 금지도 흐려짐 | 확정 정책의 필수 결과와 미정 정책별 조건부 결과를 분리 | SKILL.md, 정상·예외 패턴, 판단표, 검수 가이드 |
| 규칙과 UI가 충돌하는 상황에 단일 기대 결과를 붙일 수 있음 | 모순·수정안·결정 질문으로 남기고 임의의 합격 결과를 만들지 않음 | QA 적용 지침과 검수 체크리스트 |
| 새 점검 지침이 책의 직접 원칙으로 묶임 | 책 원칙·검증 기반 적용 지침·새 프로젝트 제안의 출처 구분 강화 | SKILL.md, 데이터 패턴, source.json |

실제 호스트에서 통과한 스킬 발견·호출 방식은 변경하지 않았습니다. 원문 21장 지식 파일, 설치 방식, 호출 이름·정책도 유지했습니다. 보완은 기존 자료 안에 반영했으며 새로운 의존성이나 실행 스크립트를 추가하지 않았습니다.

## 2. 독립 표본 검사

초기 평가자는 부모 대화 이력을 받지 않았습니다. 요청·가상 기획 메모와 현재 스킬의 관련 자료만 제공했으며 예상 답변, 발견된 문제, 원문 PDF, README·가이드, 기존 검수 기록은 제공하지 않았습니다. 결과 파일만 별도의 임시 작업 폴더에 작성했습니다.

### 자동 편성 데이터

요청마다 3명·순위 1~3을 저장하고, 같은 요청 안의 캐릭터·순위 중복은 금지하되 다른 요청에서 캐릭터를 재사용할 수 있는 가상 설정을 제공했습니다. ID 생성·저장 기술은 미정입니다.

초기 답변은 요청과 선택 행을 나누고 요청별 중복 범위를 충족했습니다. 다만 검증 기반 중복 점검을 “책에서 참고한 원칙”에 함께 묶어 출처 구분이 부족했습니다. 초기 답변을 보존하고, 스킬과 패턴에 적용 지침의 출처를 명시했습니다.

같은 평가자가 보완된 스킬을 다시 읽고 동일한 요청으로 전체 답변을 새로 작성했습니다. 최종 답변은 다음을 충족했습니다.

- 요청 행과 선택 캐릭터별 행의 의미가 일치합니다.
- `(RequestID, Rank)` 기본 키와 `(RequestID, CharacterID)` 유일성 검증을 구분합니다. 다른 요청의 동일 캐릭터는 허용합니다.
- 키만으로 정확히 3명이 저장된다는 사실을 보장할 수 없음을 밝히고, 행 개수·순위 집합·참조 존재 검증을 제안합니다.
- 요청별 결과와 캐릭터별 이력 조회를 연결하고, ID·저장 기술을 미정으로 남깁니다.
- 책의 원칙과 검증 기반 적용 지침·가상 스키마를 별도 섹션으로 구분합니다.

이는 **같은 평가자의 재생성**이며 새로운 독립 세션의 재검사로 표현하지 않습니다.

최종 경로 검사에서는 평가자의 수동 읽기 목록 중 `patterns.md`의 프로젝트 경로 오탈자도 발견했습니다. 정정 전 목록을 보존하고, 부모가 보고된 상대 경로를 올바른 프로젝트 루트에서 해석해 존재·읽기 가능 여부를 확인한 뒤 목록 한 곳을 정정했습니다. 답변 내용은 변경하지 않았습니다. 이 기록 정정은 행동 답변의 재생성이나 실제 CLI 명령 로그 검증과 별개입니다. [경로 정정 기록](behavior/read-record-correction.json)에 범위와 한계를 남겼습니다.

증거: [입력](behavior/data-input.txt) · [초기 답변](behavior/initial-data/data-answer.md) · [최종 답변](behavior/data-answer.md) · [최종 읽기 기록](behavior/data-read-files-postfix.json).

### 출석 보상 메모와 QA

가상 메모에는 `완료 && 미수령`만 수령 가능하다는 R1, 동일 요청의 중복 지급을 금지하는 R2, 재접속 후 수령 기록을 유지하는 D1, 완료 회차의 버튼을 수령 여부와 무관하게 활성화하는 U2를 제공했습니다. 응답·오류·재시도·저장 기술·갱신 타이밍은 미정입니다.

답변은 R1/D1과 U2의 충돌을 발견하고 문제·영향·수정안을 구분했습니다. 중복 요청의 추가 지급 금지를 필수 결과로 보존하면서 응답 방식과 복구 정책은 조건부 결과·결정 질문으로 남겼습니다. 표시 전용 제목에는 입력·저장 조건을 강제하지 않았습니다.

작성한 QA 시나리오 10건은 실행 계획입니다. 실제 게임에서 10건을 실행한 결과는 아닙니다.

증거: [입력과 메모](behavior/qa-input.txt) · [답변](behavior/qa-answer.md) · [읽은 자료](behavior/qa-read-files.json).

## 4. 검증 한계

이번 보완 뒤 호스트 CLI·GUI를 다시 호출하지 않았습니다. 앞선 Codex CLI 검사 결과는 당시 스킬을 대상으로 한 기록입니다. Claude Code·Antigravity 실행, 전체 프롬프트 전수 실행, 원문 재대조, 실제 게임 UI·서버·저장소 검사는 제외했습니다. 모든 답변의 정확성을 보장하는 결과는 아닙니다. 임시 작업 폴더는 증거를 보존한 뒤 정리했으며 읽기 기록의 임시 경로는 당시 검사 기록입니다.
