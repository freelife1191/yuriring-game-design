$yuriring-game-system-design 아래 보상 수령 명세를 규칙·데이터·UI 관점에서 검토해줘.
가상 기획서:
규칙 R1: 완료 상태이고 미수령인 보상을 버튼으로 직접 수령한다. 성공 후 수령 완료로 바꾼다.
규칙 R2: 같은 요청은 한 번만 반영한다. 자동 수령과 수령 만료는 미정이다.
데이터 D1: RewardEvent는 이벤트 하나를 정의하고, RewardRow는 이벤트 ID·회차·아이템 ID·수량을 가진다.
데이터 D2: ClaimRecord는 계정 ID·보상 행 ID·지급 상태를 저장한다. 행 ID의 발번 방식은 미정이다.
UI U1: 완료 상태에 수령 버튼을 활성화하고, 눌러 성공하면 완료 안내를 표시한다.
UI U2: 재접속하면 미수령 여부와 관계없이 완료 상태의 수령 버튼을 다시 활성화한다.
화면 제목은 정적 텍스트다. 실패 시 UI 처리와 재접속 시 실제 지급 기록 조회 시점은 미정이다.

자료에서 실제로 정의된 수령 자격·기록·상태를 먼저 추출해줘.
정상 수령, 중복 요청, 누락되었거나 잘못된 참조, 수령 직전 상태 변경, 재접속을 검토 후보로 삼고 해당되는 경우만 검사해줘.
각 케이스를 사전 조건·입력·기대 저장 상태·기대 UI·관련 규칙으로 연결해줘.
명세가 부족하면 정책별 가능한 결과를 나누고, 미정 값을 예상 결과로 확정하지 마.
테스트를 실제 실행한 것처럼 쓰지 말고 기획 검토용 시나리오로 표시해줘.
산출물: 모순·누락표, QA 시나리오, 합격 조건을 확정하기 위한 질문.
