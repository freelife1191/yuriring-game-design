# 출석 보상 지급 방식 비교

## 판단 전제

목표는 **접속 뒤 보상을 쉽게 확인하고 첫 콘텐츠로 자연스럽게 이동하게 하는 것**이다. 보상 종류·수량·참여 자격은 동일하므로, 아래 비교는 지급 방식이 만드는 행동과 운영 조건만 다룬다. 관측 데이터가 없으므로 유지율·매출 효과는 가설로도 수치화하지 않는다.

책의 일일 퀘스트 사례는 자동/클릭 수령과 보상 위치를 감정·흐름 설계의 선택으로 본다. 또한 규칙은 실행 순간의 실제 상태 검증과 실패 안내를 포함해야 한다. ## 동일 기준 비교

| 기준 | 자동 지급 | 직접 수령 |
| --- | --- | --- |
| 행동 단계 | 접속 → 수령 자격을 실제 상태로 판정 → 지급/실패 처리 → 지급 사실을 알림으로 확인 → 첫 콘텐츠로 이동 | 접속 → 수령 가능 상태를 인지 → 수령 버튼 선택 → 실행 시점 재판정 → 지급/실패 안내 → 다음 행동 선택 |
| 성취 피드백 | 짧은 지급 알림·인벤토리 변화·배지로 설계하면 마찰 없이 결과를 알릴 수 있다. 알림이 없거나 묻히면 지급 사실과 성취를 놓치기 쉽다. | 버튼 선택과 성공 결과가 완료감을 분명히 만들기 쉽다. 반면 매일 같은 탭·버튼을 거치면 보상이 목표보다 절차로 인식될 수 있다. |
| 피로 | 첫 콘텐츠 진입 전 조작을 줄인다. 다만 접속 직후 여러 자동 알림이 겹치면 보상 인지와 다음 행동을 모두 방해할 수 있다. | 보상을 확인하는 통제감은 있으나, 접속 때마다 필수 클릭이 되면 목표인 ‘자연스러운 이동’과 충돌할 수 있다. |
| 오류 복구 | 보관함 가득 참·지급 실패·만료 시 무엇을 자동으로 처리할지 미정이다. 지급 기록, 재시도/보관 위치, 실패 이유와 현재 상태를 함께 정해야 복구할 수 있다. | 버튼을 누른 순간의 실제 수령 가능 상태를 다시 검증하고, 실패 사유와 재시도 조건을 안내하기 쉽다. 그래도 중복 요청과 상태 경합은 서버 기준 처리와 기록이 필요하다. |
| 운영 비용 | 접속 처리·지급 기록·알림 묶음·실패 보류분의 조회/재처리 기준이 필요하다. 이는 구현·운영 측면의 추론이며, 실제 비용 크기는 프로젝트 구조에 따라 달라진다. | 수령 화면·버튼 상태·미수령 표시·상태 갱신을 유지해야 한다. 별도의 화면이 이미 있으면 추가 비용은 달라질 수 있다. |

## 조건부 추천

현재 목표에는 **자동 지급 + 짧고 누락되지 않는 확인 피드백**을 우선 검토하는 편이 맞다. 보상 수령을 별도 과업으로 만들지 않아 첫 콘텐츠 진입을 방해하지 않기 때문이다. 다만 아래 조건이 모두 충족될 때만 이 선택이 목표를 지킨다.

1. 접속 시점에 수령 자격과 지급 결과를 서버의 현재 상태로 판정한다.
2. 보관함 가득 참·지급 실패·미수령 보상 만료의 처리 결과와 복구 동선을 정한다.
3. 자동 지급 사실을 인벤토리 변화, 짧은 알림, 보상 요약 중 적어도 하나로 확인할 수 있다.
4. 자동 알림이 첫 콘텐츠의 안내보다 먼저 주의를 과도하게 빼앗지 않도록 노출 순서를 정한다.

이 조건을 충족하기 어렵거나, 해당 보상에서 **플레이어의 확인·선택 자체가 성취 경험의 핵심**이라면 직접 수령이 더 안전하다. 이때도 버튼은 보상 탭을 찾는 반복 숙제가 되지 않도록, 접속 직후의 진입 위치·미수령 표시·성공 뒤 다음 콘텐츠로 가는 동선을 함께 설계해야 한다.

## 선택지를 지지하는 조건과 반례

| 선택 | 지지하는 조건 | 반례·전환 신호 |
| --- | --- | --- |
| 자동 지급 | 보상이 정해져 있고, 수령 선택이 게임의 의미 있는 판단이 아니며, 지급 실패를 추적·복구할 기록과 동선이 있다. | 지급 사실을 알아차리지 못해 보상 가치가 약해지거나, 보관함/만료 예외에서 보상이 사라진 것처럼 보이면 직접 수령 또는 보관함 확인 단계가 필요하다. |
| 직접 수령 | 수령 행위가 일일 완료의 성취를 전달하거나, 보상 확인 뒤 선택해야 할 다음 행동이 있다. | 동일한 버튼 조작만 매일 요구되어 첫 콘텐츠 진입이 늦어지고, 선택이 실제로 아무것도 바꾸지 않으면 자동 지급이 더 의도에 맞는다. |

## 우선 확정할 정책과 검증 질문

| 우선순위 | 미정 정책 | 확인할 질문 |
| --- | --- | --- |
| 1 | 보관함 가득 참 | 자동 지급은 보류·우편 전송·대체 보관 중 무엇을 하는가? 실패 때 보상과 수령 자격은 각각 유지되는가? |
| 2 | 미수령 보상 만료 | 만료 시각·시간대·유예·사전 안내·만료 뒤 복구 가능 여부는 무엇인가? |
| 3 | 접속 직후 노출 | 자동 지급 알림, 보상 요약, 첫 콘텐츠 안내 중 어느 것을 어떤 순서와 차단성으로 보여 주는가? |
| 4 | 지급 확정과 기록 | 동일 접속/동시 요청에서 한 번만 지급되었음을 어떤 상태와 기록으로 판정하는가? |
| 5 | 검증 | 관측할 행동은 무엇인가? 예: 지급 확인 뒤 첫 콘텐츠까지의 이동 경로, 보상 관련 문의 유형, 실패/보류 보상의 회수율. 인과 효과는 관측 전 확정하지 않는다. |

> [!IMPORTANT]
> 자동 지급과 직접 수령의 우열은 보편 규칙이 아니다. 수령 방식·보상 위치·피드백은 의도한 감정과 플레이 흐름에 연결해 고르며, 원문 사례의 값이나 다른 게임의 결과를 이 프로젝트의 효과로 단정하지 않는다.
