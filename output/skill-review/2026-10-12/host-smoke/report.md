## 1. 실제 호스트 호출

- 호스트: **Codex CLI 0.162.0**. 사용자 설정의 기본 모델을 유지했으며 모델을 별도로 지정하지 않았습니다.
- 원본과 동일한 스킬 파일 **28개**를 임시 프로젝트의 `.agents/skills/yuriring-game-system-design/`에 복사했습니다. 파일별 SHA-256 일치를 확인했습니다.
- 실제 호출에는 README의 짧은 예시를 그대로 사용했습니다. 스킬 경로·본문·예상 답변을 프롬프트에 주입하지 않았습니다.
- `--sandbox read-only`, `--ephemeral`, `--skip-git-repo-check`, `--json`을 사용했습니다. 이번 실행에 한해 훅과 구성된 외부 MCP 서버를 비활성화했습니다. 사용자 설정 파일은 수정하지 않았습니다.

```text
$yuriring-game-system-design 보유량 12인 아이템 수량 스테퍼의 상태와 오류를 명세해줘. 기본 수량은 미정이야.
```

CLI 로그에서 스킬을 사용하겠다는 안내 뒤 다음 자료를 실제로 읽었습니다. 읽기 명령 종료 코드와 CLI 종료 코드는 모두 **0**이며, `turn.completed` 이벤트와 최종 답변을 확인했습니다.

**답변에서 확인한 내용:** 기본 수량은 미정으로 유지했고, 12에서 증가 버튼을 비활성화했습니다. 직접 입력 오류·보유량 변경·처리 중 상태를 다뤘으며, 최소 수량 1과 직접 입력 지원은 가정 또는 제안으로 표시했습니다. 포커스·호버는 입력 환경에 따라 적용했습니다.

## 2. 고급 프롬프트 표본 검사

각 초기 평가자는 요청과 스킬의 관련 자료만 받았습니다. 원문 PDF, README·고급 가이드, 기존 검수 기록, 다른 평가자의 답변이나 기대 정답은 제공하지 않았습니다. 요청 텍스트는 가이드의 해당 예시에서 그대로 추출했습니다.

### 12장 B — 주말 랜덤 상점

- 하루 두 번 갱신과 세 상품 타입은 가상 입력으로 표시했습니다.
- 독립 추출·중복 허용·이력 보존·갱신 시각은 결정 질문으로 남겼습니다.
- 확률과 상대 비중을 구분하고, 비중 30·70·20의 합계 120을 오류로 처리하지 않는 검토 예시를 제시했습니다.
- 그룹 조회와 단일 행 참조를 구분했습니다. 타입 불일치·고아 ID·빈 풀·분모 0 반례에 결정 책임과 보류 사유를 붙였습니다.

증거: [입력](prompts/ch12-input.txt) · [답변](prompts/ch12-answer.md) · [읽은 자료](prompts/ch12-read-files.json).

### 18장 A — 자동 원정 편성

초기 답변은 `조건 점수 → 등급 → 레벨 → 캐릭터 고유 ID`를 보존하고 정렬 방향·보상·동기화를 미정으로 유지했습니다. 정원 부족·동점·후보 없음·상태 변경·취소 QA도 포함했습니다.

다만 `ExpeditionFormationResult`를 “자동 편성 1회 결과”로 설명하면서 `SelectedCharacterID`, `Rank`를 단일 필드로 두어, 4명 결과를 몇 행으로 저장하는지와 기본 키가 명확하지 않았습니다. 따라서 초기 판정은 **부분 통과**입니다.

[고급 활용법의 해당 예시](../../../../docs/advanced-usage.md#chapter-18)에 아래 한 문장을 추가했습니다. 스킬의 기존 행·키·참조 원칙을 구체적인 요청에 반영한 보완입니다.

```text
각 테이블은 한 행의 의미·기본 키·중복 검증 범위를 명시하고, 단일 행 참조와 그룹 조회를 구분해줘.
```

보강 후 답변은 요청 1건과 선택 후보 1명을 별도 행으로 정의했습니다. 선택 행마다 기본 키를 두고, 요청별 순위·후보 중복을 검증하며 같은 요청의 선택 행을 조회해 최대 4명 결과를 얻도록 설명했습니다. 초기의 우선순위·미정 정책·QA 조건도 유지해 **통과**로 판정했습니다.

재검사는 **같은 평가자가 갱신 입력으로 전체 답변을 다시 생성한 검사**입니다. 새 독립 세션에서 반복한 결과로 표현하지 않습니다.

증거: [초기 입력](prompts/initial-ch18/prompt-ch18.txt) · [초기 답변](prompts/initial-ch18/ch18-answer.md) · [보강 후 입력](prompts/ch18-input.txt) · [보강 후 답변](prompts/ch18-answer.md) · [재검사 읽기 기록](prompts/ch18-read-files-postfix.json).

## 3. 변경과 검증

- [고급 활용법](../../../../docs/advanced-usage.md): 18장 A의 행·키·참조 요청 한 문장 추가.
- [검수 가이드](../../../../docs/validation.md): 이 호출·표본 검사 기록으로 연결하는 안내 추가.
- 스킬 **28개 파일과 README는 변경하지 않았습니다**. 실제 생성된 답변의 의미를 기준으로 판정했으며, 키워드 포함만으로 통과 처리하지 않았습니다.
- 기존 42개 장별 예시·21개 후속 요청·4개 공통 프롬프트·3개 연계 시나리오를 유지했습니다.

자세한 판정 근거는 [행동 검사 기록](behavior-checks.json), 구조·링크·파일 보존 확인은 [검증 기록](validation.json), 범위와 한계는 [구조화 보고서](report.json)에 있습니다.

## 4. 검증 한계

Codex 데스크톱 GUI, Claude Code, Antigravity에서의 호출은 실행하지 않았습니다. 원문 재대조와 실제 게임 UI·데이터·서버의 런타임 검사도 제외했습니다. 초기 독립 표본은 3개이며 전수 검사는 아닙니다. 임시 프로젝트와 평가 작업 폴더는 증거를 보존한 뒤 정리했습니다. 로그의 임시 경로는 당시 실행의 기록입니다.
