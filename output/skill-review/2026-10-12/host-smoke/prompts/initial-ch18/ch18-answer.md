# 자동 원정 편성 기능 협업 기획서

## 근거와 적용 범위

| 구분 | 내용 |
|---|---|
| **책의 사실** | 18장의 파견 미션 사례는 자동 배치에서 `조건 점수 → 등급 → 레벨 → 캐릭터 고유 ID` 순으로 우선순위를 비교한다. 자동화는 수동 편성보다 항상 최적일 필요는 없으며, 대상 가능 조건·우선순위·동점·실패 피드백·결과 상태를 명세해야 한다. |
| **가상 프로젝트 가정** | 정원은 4명이다. 같은 캐릭터의 중복 배정은 금지한다. 휴식 중 캐릭터는 후보에서 제외한다. |
| **이 문서의 제안** | 아래 상태·데이터·UI·QA 형식은 협업 구현을 위해 위 사실과 가정을 적용해 구성한 초안이다. 프로젝트에 없는 정책을 확정하지 않는다. |

> [!IMPORTANT]
> `조건 점수 → 등급 → 레벨 → 캐릭터 고유 ID`는 비교 **순서**만 확정되어 있다. 각 기준의 오름차순·내림차순은 미정이므로, 이 문서는 특정 캐릭터가 먼저 선택된다고 단정하지 않는다.

## 1. 개요

### 문제

출전 후보가 많을 때 플레이어가 조건을 반복 비교해 원정 인원을 채워야 한다. 자동 편성은 이 반복 판단을 줄이되, 사용자가 이해할 수 있는 기준과 예외를 제공해야 한다.

### 목표

후보 가능 여부를 확인한 뒤, 확정된 정렬 방향으로 우선순위를 비교하여 최대 4명의 자동 편성 결과를 제시한다. 정원 부족·상태 변경·취소가 발생하면 잘못된 편성을 확정하지 않고 이유를 알린다.

### 타깃

여러 캐릭터 중 원정 출전자를 빠르게 구성하려는 플레이어와, 후보 상태·우선순위·편성 결과를 동일한 규칙으로 확인해야 하는 기획·클라이언트·서버·QA 담당자.

### 구성 요소

1. 후보 조회 및 가능/제외 사유 판정
2. 조건 점수·등급·레벨·캐릭터 고유 ID 비교
3. 최대 4명 자동 선택과 중복 배정 검증
4. 결과 미리보기·실패 안내·취소 처리
5. 후보 상태·정렬 입력·검증 결과를 연결하는 데이터와 QA 케이스

## 2. 본문 규칙

### 2.1 상태

| 상태 | 진입 조건 | 표시·입력 | 결과 |
|---|---|---|---|
| 후보 조회 중 | 자동 편성 요청을 시작함 | 후보 목록과 자동 편성 입력을 처리 중으로 표시하는 방안을 제안한다. | 최신 후보 정보를 받은 뒤 판정한다. |
| 편성 가능 | 중복 배정이 아니고 휴식 중이 아닌 후보가 4명 이상임 | 자동 편성 실행과 결과 확인 입력을 허용하는 방안을 제안한다. | 정렬 방향이 확정되면 상위 4명을 결과로 제시한다. |
| 정원 부족 | 가능한 후보가 1~3명임 | 부족 인원과 제외 사유를 표시한다. 자동 확정 입력은 허용하지 않는 방안을 제안한다. | 편성을 확정하지 않는다. |
| 후보 없음 | 가능한 후보가 0명임 | 후보 없음과 제외 사유를 표시한다. 자동 확정 입력은 허용하지 않는 방안을 제안한다. | 편성을 확정하지 않는다. |
| 편성 결과 검증 중 | 자동 선택 결과가 생성된 뒤 확정 전임 | 취소 입력의 처리 가능 시점은 미정이다. | 후보 상태를 다시 검증한다. |
| 결과 무효 | 검증 중 후보가 휴식·중복 배정 등으로 바뀜 | 변경된 후보와 재실행 필요 여부를 표시하는 방안을 제안한다. | 결과를 확정하지 않고 후보 조회로 돌아간다. |
| 취소됨 | 사용자가 취소를 요청함 | 취소 결과와 되돌림 범위는 표시해야 한다. | 이미 확정된 배정·보상·서버 반영을 되돌리는 정책은 미정이다. |

### 2.2 조건과 판정

| 순서 | 판정 | 확정 범위 | 결과 |
|---|---|---|---|
| 1 | 후보가 중복 배정 상태인가? | 중복 배정 금지는 가상 프로젝트 가정 | 해당 후보를 제외하고 사유를 기록한다. |
| 2 | 후보가 휴식 중인가? | 휴식 중 제외는 가상 프로젝트 가정 | 해당 후보를 제외하고 사유를 기록한다. |
| 3 | 가능한 후보가 4명 이상인가? | 정원 4명은 가상 프로젝트 가정 | 미만이면 정원 부족, 0명이면 후보 없음으로 종료한다. |
| 4 | 가능한 후보를 조건 점수로 비교한다. | 비교 순서는 책의 사실 | 오름·내림 방향은 미정이다. |
| 5 | 조건 점수가 같으면 등급, 다시 같으면 레벨, 다시 같으면 캐릭터 고유 ID를 비교한다. | 비교 순서는 책의 사실 | 각 기준의 방향이 확정된 뒤에만 순위를 결정한다. |
| 6 | 정렬된 후보 상위 4명을 선택한 뒤 상태를 다시 검증한다. | 재검증은 이 문서의 제안 | 하나라도 불가가 되면 결과 무효로 처리한다. |

> [!WARNING]
> 캐릭터 고유 ID까지 비교하므로 동일한 네 기준으로 완전히 동률인 서로 다른 후보는 전제하지 않는다. 단, 고유 ID의 비교 방향도 미정이므로 현재는 마지막 동점 해소 결과를 계산할 수 없다.

### 2.3 결과와 예외

| 상황 | 결과 | 플레이어 피드백 | 정책 상태 |
|---|---|---|---|
| 후보 4명 이상, 정렬 방향 확정 | 상위 4명을 편성 결과로 제시 | 선택 기준과 제외 후보 사유 | 결과 제시는 제안, 정렬 방향은 미정 |
| 정원 부족 | 편성을 확정하지 않음 | 가능한 후보 수/필요 인원/제외 사유 | 가상 정원 기준 |
| 후보 없음 | 편성을 확정하지 않음 | 후보 없음 및 제외 사유 | 가상 제외 기준 |
| 편성 중 후보 상태 변경 | 결과를 무효화하고 재조회 | 변경 항목과 재실행 안내 | 재검증·무효화는 제안 |
| 취소 | 취소 요청을 기록 | 처리 완료/실패/확정 후 영향 표시 | 취소 시점·되돌림 범위 미정 |

## 3. 데이터 명세 제안

아래는 구현 테이블을 확정하는 지시가 아니라, 자동 편성 판정에 필요한 데이터를 협업자가 같은 의미로 읽기 위한 제안이다.

| 데이터 | 한 행/값의 의미 | 주요 필드 | 참조 | 검증 규칙 |
|---|---|---|---|---|
| `ExpeditionCandidateSnapshot` | 특정 원정 요청 시점의 후보 한 명 | `CandidateID`, `CharacterID`, `CandidateState`, `IsResting`, `AssignmentState` | `CharacterID` → 캐릭터 정의 | `CandidateID`는 유일해야 하며, `CharacterID`가 동일한 후보를 두 번 선택하지 않는다. |
| `CandidatePriority` | 후보 한 명의 자동 편성 비교값 | `CharacterID`, `ConditionScore`, `Grade`, `Level` | `CharacterID` → 캐릭터 정의 | 네 비교값이 판정 가능한지 확인한다. 각 값의 정렬 방향은 설정 또는 정책으로 별도 확정한다. |
| `ExpeditionFormationResult` | 자동 편성 1회 결과 | `RequestID`, `SelectedCharacterID`, `Rank`, `ValidationState` | `RequestID` → 요청, `SelectedCharacterID` → 캐릭터 정의 | 선택 캐릭터 수는 최대 4명, `SelectedCharacterID`는 결과 안에서 유일, 확정 전 최신 후보 상태를 다시 검증한다. |
| `CandidateExclusion` | 후보가 제외된 사유 | `CandidateID`, `ReasonCode` | `CandidateID` → 후보 스냅샷 | 현재 가정의 사유는 `AlreadyAssigned`, `Resting`이다. 추가 사유의 허용 목록은 미정이다. |

> [!NOTE]
> 조건 점수·등급·레벨의 실제 저장 위치, 스냅샷 보존 기간, 요청 ID의 생성 방식은 서버 동기화 방식과 함께 미정이다. 이 문서는 이를 임의의 영속 구조로 확정하지 않는다.

## 4. UI 명세 제안

| 화면/요소 | 상태별 표시 | 입력 가능 여부 | 입력 또는 결과 |
|---|---|---|---|
| 원정 후보 목록 | 후보마다 조건 점수·등급·레벨·고유 ID와 가능/제외 사유를 표시하는 방안을 제안한다. | 목록은 표시 전용이다. | 정렬 방향이 미정이면 방향 미확정 상태를 함께 표시한다. |
| 자동 편성 버튼 | 편성 가능/정원 부족/후보 없음/검증 중/결과 무효를 구분한다. | 편성 가능 상태에서만 실행 가능하게 하는 방안을 제안한다. | 실행 후 결과 미리보기 또는 실패 안내로 이동한다. |
| 편성 결과 영역 | 선택된 최대 4명, 후보 순위, 제외 사유, 재검증 상태를 표시한다. | 확정·취소 입력의 정확한 활성 조건은 미정이다. | 상태 변경이면 결과 무효와 재실행 안내를 보인다. |
| 취소 입력 | 취소 가능 여부와 취소 후 영향 범위를 표시한다. | 확정 전/후 각각의 가능 여부는 미정이다. | 보상·배정·동기화에 미치는 영향은 미정 질문으로 남긴다. |
| 안내 메시지 | 정원 부족·후보 없음·상태 변경·취소 처리 결과를 구분한다. | 정적 안내 문구에는 입력·저장 규칙을 강제하지 않는다. | 메시지 문구와 노출 시간은 프로젝트에서 결정한다. |

## 5. QA 케이스

| ID | 사전 조건/입력 | 기대 확인 | 미정 또는 추가 확인 |
|---|---|---|---|
| QA-01 정원 부족 | 가능한 후보가 3명이고 나머지는 중복 배정 또는 휴식 중 | 4명 편성 결과를 확정하지 않고, 가능한 수와 제외 사유를 표시한다. | 부분 편성을 제안할지 여부 |
| QA-02 동점 | 조건 점수·등급·레벨이 같은 후보 둘의 고유 ID가 다름 | 고유 ID가 마지막 비교 기준으로 사용됨을 확인한다. | 고유 ID의 오름·내림 방향과 실제 선택 결과 |
| QA-03 후보 없음 | 모든 후보가 중복 배정 또는 휴식 중 | 편성을 확정하지 않고 후보 없음과 사유를 표시한다. | 추가 제외 사유 목록 |
| QA-04 편성 중 상태 변경 | 결과 생성 뒤 확정 전, 선택 후보 하나가 휴식 또는 중복 배정 상태로 변경됨 | 최신 상태 재검증에서 결과를 무효화하고 재실행 안내를 표시한다. | 변경 감지 시점, 재시도 방식, 서버 동기화 방식 |
| QA-05 취소 | 자동 편성 결과가 표시된 상태에서 취소 요청 | 취소 요청의 성공/실패와 영향 범위를 사용자에게 표시한다. | 취소 가능 시점, 확정된 배정·보상·서버 반영의 되돌림 정책 |

## 6. 미확정 질문

1. 조건 점수·등급·레벨·캐릭터 고유 ID는 각각 오름차순과 내림차순 중 어느 방향으로 비교하는가?
2. 자동 편성 또는 원정 완료에 보상이 있는가? 있다면 지급 조건·수량·취소/실패 시 처리 규칙은 무엇인가?
3. 후보 조회, 결과 확정, 상태 변경, 취소를 서버와 어떤 시점·권한·재시도 규칙으로 동기화하는가?

## 협업 인계 기준

- **기획:** 세부 정렬 방향, 취소 범위, 보상 정책을 확정하고 가정으로 둔 정원·제외 조건을 실제 정책으로 승인 또는 변경한다.
- **개발:** 확정된 비교 방향과 상태 재검증 시점을 입력으로 받아 중복 배정 방지 및 동기화 책임을 설계한다.
- **UI/UX:** 상태별 버튼 활성·비활성, 제외 사유, 취소 영향 안내를 실제 입력 장치와 화면 흐름에 맞춰 확정한다.
- **QA:** 위 다섯 케이스에 확정 정책을 채운 뒤, 후보 조회부터 취소 또는 재실행까지의 실제 환경 검증 케이스로 확장한다.
