# 문제 해결

[가이드 홈](index.md) · 관련: [에이전트별 사용](agents.md), [검수와 테스트](validation.md)

`yuriring-game-system-design`을 호출했는데 스킬을 찾지 못하거나, 답변에 조건·근거·설계 연결이 빠졌을 때의 점검 순서입니다. 먼저 현재 프로젝트 경로와 실제 요청을 확인한 뒤 필요한 부분만 보완합니다.

> [!TIP]
> **먼저 할 일**
>
> 스킬 이름, 프로젝트 위치, 요청에 넣은 목표·제약·기획안 내용을 한 번에 확인하세요. 같은 요청을 반복하기 전에 빠진 정보와 원하는 산출물을 좁히는 편이 빠릅니다.

---

## 증상별 대응

| 증상 | 먼저 확인 | 다음 요청 또는 조치 |
|---|---|---|
| 스킬을 찾지 못함 | 프로젝트 루트와 `SKILL.md` 경로 | [에이전트별 사용](agents.md)의 경로·링크 확인 후 새 세션에서 재탐색 |
| 호출 이름이 동작하지 않음 | `yuriring-game-system-design` 철자 | 프로젝트명과 호출 ID를 혼동하지 않고 정확한 ID 사용 |
| 일반적인 답변만 나옴 | 목표·장르·대상·제약 제공 여부 | 기능의 맥락과 원하는 결과 형식을 추가 |
| 질문에 맞는 장을 못 찾음 | [참조 자료 색인](../.agents/skills/yuriring-game-system-design/references/index.md)의 사례·검색어 | 장 번호 대신 구체적인 기능·테이블·UI 이름으로 요청하고 실제 읽은 파일을 확인 |
| 답변의 근거 링크가 열리지 않음 | 링크가 실제 읽은 파일을 가리키는지 | 존재하지 않는 추정 경로를 고치고, 책/PDF쪽과 새 제안의 구분도 확인 |
| 규칙에 예외가 없음 | 실패·취소·중복·동시 처리 질문 포함 여부 | 조건 → 처리 → 결과 → 실패·취소·충돌 순서로 재요청 |
| 수치가 임의로 확정됨 | 근거와 결정권자가 있는지 | 선택지·영향·담당자 표로 남기도록 요청 |
| 데이터가 중복되거나 연결이 불명확함 | 행 의미·키·참조 대상 | 10~12장을 지정해 사용·업데이트 빈도, 수정 범위, 재사용성에 따른 분리·통합 비교 요청 |
| UI와 규칙이 어긋남 | 성공·실패 상태와 처리 조건 | 13~16장을 지정해 요소별 상태·피드백·저장 여부를 대조 |
| 책의 내용인지 새 제안인지 모호함 | 출처·가정 구분 요청 여부 | 책의 설명, 프로젝트 제안, 미결정을 구분하도록 재요청 |
| 원문의 수치·도식이 의심됨 | 원본 PDF와 `source.json` 한계 | 해당 페이지를 제공하거나 직접 대조 후 수정 요청 |
| 문서 변경 영향이 불명확함 | 재화·보상·기록·UI·운영 연결 | 20~21장 기준으로 영향 범위와 우선순위 분석 요청 |

## 스킬을 찾지 못할 때

프로젝트 루트에서 다음 경로를 확인합니다.

```text
.agents/skills/yuriring-game-system-design/SKILL.md
```

Claude Code를 사용한다면 아래 링크도 확인합니다.

```text
.claude/skills/yuriring-game-system-design
```

> [!IMPORTANT]
> **파일 확인과 앱 탐색을 구분합니다**
>
> 파일이나 링크가 존재해도 현재 실행 중인 앱이 이미 스킬을 로드했다는 뜻은 아닙니다. 프로젝트를 올바른 루트로 열었는지 확인하고 새 세션에서 다시 탐색하세요. 앱별 세부 사항은 [에이전트별 사용](agents.md)을 따릅니다.

## 조건이 빠진 답변을 보완할 때

참조 자료가 선택되지 않았다면 “참조 색인에서 이 질문에 맞는 장을 고르고, 먼저 읽은 파일과 확인한 쪽 범위를 알려줘”라고 요청합니다. 장 파일만으로 원문의 정확한 칼럼명·도판을 확인할 수 없는 경우에는 해당 PDF쪽 확인이 필요합니다.

```text
$yuriring-game-system-design 아래 초안을 다시 검토해줘.
1) 적용 조건, 2) 처리 순서, 3) 성공·실패·취소·중복 처리,
4) 필요한 데이터와 참조, 5) UI 상태와 안내를 각각 분리해줘.
확인되지 않은 사실은 추정하지 말고 ‘결정이 필요한 사항’ 표에 정리해줘.

[초안]
```

특정 영역만 부족하면 장을 명시합니다.

- 규칙과 플로 차트: **7~9장**
- 키·참조·보상 테이블: **10~12장**
- 화면·요소 상태·피드백: **13~16장**
- 문서 완성도·변경 영향·협업: **17~21장**

## 원문 확인이 필요한 경우

`source.json`은 원본의 식별 정보와 한계를 기록하지만, 모든 표·그림·스크린샷의 의미를 전수 검증한 자료는 아닙니다. 다음 경우에는 원문 PDF의 해당 부분을 확인하거나 제공하세요.

- 확률, 시간, 재화 수량 등 정확한 수치가 필요한 경우
- 테이블 열의 연결과 식별자 관계를 확정하는 경우
- 플로 차트의 분기 순서나 UI 상태 전이를 해석하는 경우
- 책 예시를 현재 프로젝트 정책으로 채택하려는 경우

> [!WARNING]
> **미결정 정책을 사실처럼 다루지 마세요**
>
> 원문에 예시가 있어도 현재 게임의 보상, 제한, 운영 정책이 자동으로 정해지는 것은 아닙니다. 결정할 사람과 시점이 정해질 때까지 선택지와 영향을 남겨 두세요.

## 파일 변경 이후 영향 확인

스킬의 장 파일, `references/index.md`, 용어집, 패턴, 판단표, `SKILL.md`를 수정했다면 다음을 함께 점검합니다.

1. 장·주제 색인의 링크가 실제 파일을 가리키는지 확인합니다.
   참조 색인에서 연결한 장·보조 자료도 포함하며, 스킬 폴더만 다른 경로에 복사해도 내부 참조가 유지되는지 확인합니다.
2. 수정한 원칙이 다른 장의 설명이나 예시와 모순되지 않는지 확인합니다.
3. `source.json`의 출처·장 범위·한계 기록과 충돌하지 않는지 확인합니다.
4. 수정 전 문제가 재현되는 실제 요청으로 다시 답변을 평가합니다.

변경 범위가 클수록 [검수와 테스트](validation.md)의 원문 대조와 실제 답변 평가를 함께 수행하세요.
