## 스킬이 하는 일

```text
사용자 목표·프로젝트 제약
        ↓
관련 장을 읽어 판단 기준 선택
        ↓
기획 의도 · 규칙 · 데이터 · UX/UI · 기획서 산출물 작성 또는 검토
        ↓
가정 · 미결정 사항 · 원문 근거를 구분해 다음 결정으로 연결
```

| 요청 유형 | 주로 참조하는 장 | 대표 산출물 |
|---|---|---|
| 기능의 필요성을 설명한다 | 3–4장 | 문제·역할·감정·플레이 흐름 |
| 시스템 구조와 규칙을 설계한다 | 5–9장 | 기능 분해, 조건·결과·예외, 플로 차트 |
| 데이터 테이블을 만든다 | 10–12장 | 행 의미, 열·타입·키·참조 관계 |
| 화면과 조작을 정의한다 | 13–16장 | 정보 구조, 화면 흐름, 요소 명세 |
| 기획서를 정리하거나 검토한다 | 17–19장 | 독자별 문서, 누락·모순·수정안 |
| 개발·라이브 변경을 판단한다 | 20–21장 | 변경 영향, 우선순위, 협업 기준 |

> [!IMPORTANT]
> **스킬의 역할**
>
> 스킬은 책의 판단 기준을 프로젝트 상황에 적용하는 도구입니다. 장르, 대상 이용자, 기존 시스템, 일정, 기술 제약이 주어지지 않으면 답변은 이를 **가정** 또는 **결정이 필요한 사항**으로 표시해야 합니다.

## 자료 구성과 확인 범위

스킬의 실제 원본은 [SKILL.md](../.agents/skills/yuriring-game-system-design/SKILL.md)이며, 21개 장 파일·참조 색인·용어집·패턴·판단표·출처 기록으로 구성됩니다. 참조 색인은 기존 지식 자료를 질문별로 연결하며, 장 파일을 중복 복제한 자료가 아닙니다.

- [장별 자료](../.agents/skills/yuriring-game-system-design/chapters/) — 각 장의 개념과 적용 기준
- [참조 자료 색인](../.agents/skills/yuriring-game-system-design/references/index.md) — 구체적인 질문·테이블·UI·사례별로 먼저 읽을 장과 보조 자료 선택
- [용어집](../.agents/skills/yuriring-game-system-design/glossary.md) — 핵심 용어
- [실무 패턴](../.agents/skills/yuriring-game-system-design/patterns.md) — 반복해서 쓰는 설계 방식
- [판단표](../.agents/skills/yuriring-game-system-design/cheatsheet.md) — 빠른 점검 기준
- [출처·한계 기록](../.agents/skills/yuriring-game-system-design/source.json) — 원본 정보, 쪽 규약, 검수 범위

> [!WARNING]
> **원문 확인이 필요한 경우**
>
> 확률·시간·수치, 열 연결, 도식의 방향, 책 예시의 적용 조건을 결정할 때는 원본 PDF의 해당 페이지를 확인하세요. `source.json`은 PDF 쪽과 책 인쇄 쪽의 차이, 추출·검수 한계를 기록합니다. 이 기록은 원문 전체를 대신하지 않습니다.

## 문서 사용 원칙

1. 요청에 맞는 장만 먼저 읽고, 모든 장을 한 번에 적용하지 않습니다.
2. 책의 설명, 스킬의 재구성, 현재 프로젝트를 위한 새 제안을 서로 구분합니다.
3. 정책·수치·담당자가 정해지지 않았다면 임의로 확정하지 않습니다.
4. 검토는 **문제 → 플레이·구현 영향 → 수정안** 순서로 적습니다.

다음 단계는 [시작하기](getting-started.md)에서 현재 프로젝트에 맞는 첫 요청을 고르는 것입니다.
